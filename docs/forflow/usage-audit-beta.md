# AI 用量：费用口径与审计覆盖 Beta

2026-09-20。用户要求在“审计与用量是运行事件的不同投影”的基础上，明确估算、已结算、套餐分摊、不可计量，并分别说明上下文、模型调用、工具调用、数据读取的覆盖程度。

用户随后明确纠正：“不是，这个页面是让你设计完融入统计与使用情况中作为beta功能”。`.22` 的页尾长说明不再作为交付方案；保留其已验证的计量投影，`.23` 把交互融入既有统计界面。用户再次指出“费用／审计 Beta 没有实际数据”“账单不是codex也有，套餐也是”。`.24` 据此接入已有账户信息和 Codex 日志审计片段；不再把未接线描述为没有数据来源。

## 在统计页中的位置

- **成本卡片**：概览及 Claude、Codex、OpenCode 原成本位置支持切换“估算／已结算／套餐分摊／不可计量”。金额、缺价数和未知状态直接出现在统计卡片内，每次只看一种口径，不累计四种值。
- **审计覆盖 Beta**：紧接统计卡片、位于趋势和明细之前。上下文、模型调用、工具调用和数据读取分别显示状态；默认收起解释，点击任一项展开现有证据与待补证据，再次点击收起。同一时间只展开一项。
- **来源与范围**：在审计标题旁按需展开实际来源、扫描时间、时间窗口、工作区范围和金额来源。沿用现有提供商选择与筛选，不另造一套过滤器。
- **空白与异常**：无记录时显示“暂无金额／暂无可核验记录”；读取异常保留上次快照并提示刷新。来源未启用时不复用缓存作为当前证据。Grok 原套餐额度页面保留，不把额度折成费用。

保留原 Token、趋势、模型／项目／会话明细及刷新流程。当前 Beta 使用用量快照、账户额度和有界日志明细，统一运行事件审计链仍是后续工作。

## 四类费用

| 口径     | 本版数据来源与行为                                                                                    | 后续完整计量需要                                                                             |
| -------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 估算     | Claude/Codex 已读 Token 与内置价格表；OpenCode 本地日志申报金额。展示美元已知部分，缺价不混成完整总额 | 定价版本、模型映射、缓存和重试规则、记录与运行关联；估算不能代替账单                         |
| 已结算   | 显示“待对账金额”；Codex／概览提供官方用量与账单入口，金额不填零                                                                          | 供应商原始账单、币种、账期、账单行 ID、对账凭据及修订记录                                    |
| 套餐分摊 | 显示“未配置分摊”，不根据账户套餐或 Token 占比猜费用                                                   | 实付金额、有效账期、规则版本、项目归属、分摊分母、未分配部分；分摊合计不得超过对应可分摊金额 |
| 不可计量 | 显示已读记录的明确缺价数、逐条完整性未知数；无记录时为“尚无法判断”                                    | 缺失原因、影响范围、补采或对账结果；无日志和缺价均不等于免费                                 |

这四种口径不是四笔可以相加的支出。同一活动可能先估算、后对账，再按项目分摊；必须靠活动 ID／账单行 ID 关联版本，避免重复计费。不同币种分别汇总，换算需显式汇率及日期。本版金额仍为既有美元估算；账户余额复用已有 Codex 登录与额度读取，不增加模型调用或扣费操作。官方账单在用户点击后打开，尚未自动同步账单行。

新增可选 `costCoverage = { pricedRecords, unpricedRecords, unclassifiedRecords }` 字段。Claude 的记录单位是已扫描轮次，Codex 是计量事件；两者都不是完整请求次数。统计与原有金额使用同一范围和时间过滤，支持文件夹工作区。OpenCode 的历史每日金额可能已将缺价事件折叠进小计，因此金额非空的聚合仍归为逐条完整性未知，不倒推全覆盖。不重写历史缓存；旧服务缺少字段或计数不一致时按未知处理。

## 四项审计覆盖

| 维度     | 当前页面如实展示                                                           | 尚缺的证据                                                |
| -------- | -------------------------------------------------------------------------- | --------------------------------------------------------- |
| 上下文   | Codex 近期日志中的回合上下文及压缩记录，包含时间和源文件偏移；其他提供商待接入                         | 调用实际输入版本、来源授权、脱敏与裁剪、发送回执          |
| 模型调用 | Codex 新格式的 response_id 与该次 Token 数；旧 token_count 仍用于原统计，不重复计为模型请求 | 缺失请求的 ID、失败和重试、实际模型路由、全部调用分母、账单核对 |
| 工具调用 | Codex 的工具名称、call_id、对应返回记录、日志时间与字节偏移；返回存在不代表成功                                           | 调用与执行主机、参数摘要、权限决定、结果、证据引用        |
| 数据读取 | 项目／路径归属只是统计信息，本账本尚未接入                                 | 文件版本、表／字段范围、主体、授权依据、实际读取结果      |

按来源显示实际快照的范围、时间窗口、扫描时间和状态；读取失败保留“上次快照”提示。关闭来源不把其旧数据作为当前证据，Grok 套餐额度不复用其他来源的 Token 或金额。未接入的 SSH／其他主机不计为覆盖，不能从本机空白推断远端没有活动。

没有全部活动分母时不展示覆盖百分比；没有可信事件／结果关联时不展示“完整覆盖”。后续若展示比例，必须同列：应采集数量、成功关联数量、明确缺口数量、未知数量、来源主机、时间窗口和计算规则。来源记录本身缺失的调用不能藏在已读记录的分母之外。

## Codex 账户与有界日志明细（.24）

- 账户读取保留 `planType`、`credits.hasCredits/unlimited/balance`，RPC 优先使用 `rateLimitsByLimitId.codex`。兼容只返回旧单桶和不返回账户元数据的服务。
- 账户卡片使用原状态栏的账户源：套餐、剩余额度点数、5 小时／每周使用及重置时间。账户范围和更新时间可见，不随日志项目或日期筛选变化。缺失余额与真实零余额分开。
- `account/rateLimits/read` 的额度单位不自动赋予货币；`token_usage_record` 是带响应编号的 Token 记录，本身没有金额。官方文档：[App Server](https://learn.chatgpt.com/docs/app-server)、[用量说明](https://learn.chatgpt.com/docs/pricing)。
- 新增可选 `codexUsage.getAudit` 只允许已有 scope/range 枚举；主进程从已扫描索引选文件，不接受界面传入任意文件路径。最多近期 8 个候选文件，每个 2 MiB 尾部；展示候选数、成功数、截断数、错误与范围未知数，每类最多 12 条明细。
- 保留原缓存 schema 与增量用量扫描，审计只读不持久化另一份正文。30 秒短缓存合并相同查询。筛选变化立即撤下旧审计快照，旧运行端缺方法时明确提示。
- 单条事件按时间及当时的工作目录过滤；尾部缺少上下文时不借用文件末尾目录猜前面事件归属。按响应／调用编号去重，工具返回与调用关联。参数与输出正文不进入界面。
- 现阶段数据读取仍缺受控访问审计源；不通过解析任意 `exec` 命令猜哪些数据已读取，不给覆盖百分比。
- 开发态真实只读验证：102 个候选中抽读 8 个文件、7 个截断尾部，得到上下文 38、响应 316、工具 311，其中 310 有返回。现有 Forflow 后端读取账户 HTTP 200，套餐 Pro、额度余额 0；这些是本次观测，不是固定测试数据或整月总量。原始摘要收据在 `.forflow/evidence/forflow24-real-{audit,account}.json`，无提示词及账户凭据。

## 后续小步补全

1. 将 B0 上下文回执以事件 ID 与具体发送／调用关联；先核验单个 Codex 会话，不抓取全盘正文。
2. 为模型和工具事件增加执行主机、尝试 ID、结果和证据引用；重放去重，失败也记录。敏感正文按权限保存摘要或引用。
3. 从受控读取入口采集实际数据访问与授权证据，不把终端文本推断作为事实。
4. 单独接入只读账单，完成对账后再增加分摊规则。用户确认实际账期与分摊依据前不生成“已结算”或“套餐分摊”金额。

新增字段仅为原用量快照的可选扩展。远端旧版本可省略，新客户端展示未知；不改变远程终端、Agent 状态或已有授权策略。
