# 从 Codex 学习任务操作

日期：2026-09-20。对象：团队与客户 AI／研发人员使用的 Forflow One。用户原话：“有些操作易用性上得考虑，学习一下codex，codex这块还是可以的”。

本次用 Codex 官方文档研究交互机制，用隐藏 Electron 的真实界面检查 Forflow；没有声称已操作或完整审计 Codex 桌面端。开发前基线为 `e30c4f9d842bb56b1f2b80a07975e808e7a23d36`，对应 `.13`。本轮修复进入 `.14`，安装和验证状态见本版发布记录。

## 改变判断的证据

1. Codex 把项目作为共享资料和目录，把独立任务作为明确产出的会话；从自然语言目标开始，不要求先填满配置。[项目与会话](https://learn.chatgpt.com/docs/projects)、[输入任务](https://learn.chatgpt.com/docs/prompting)。
2. Codex 明确区分执行中立即补充与下一轮排队，并允许管理待发送消息。Forflow 当前桥接会话只是把输入交给原 CLI；各 CLI 的实际行为不同，不能仅加一个“排队”按钮就声称相同能力。[补充与排队](https://learn.chatgpt.com/docs/prompting#steering-and-queuing)。
3. Codex 的审阅面板展示工作目录真实的 Git 更改，可逐行反馈。范围包含人工和其他进程修改，并不天然等同于本次 Agent 产物。[代码审阅](https://learn.chatgpt.com/docs/code-review)。

因此，Forflow 后续应围绕“输入目标与材料 → 看见正在做什么 → 补充或处理待确认事项 → 查看结果并反馈”组织操作。终端保留为专业操作入口。

## 本轮实际检查的流程

使用 `.forflow/evidence/usability-before/` 当前采集的 `.13` 截图，未复用旧截图作为本次审查证据。

| 步骤                    | 观察                                                             | 处理                                                                             |
| ----------------------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 1. 进入同会话对话视图   | 对话／终端可切换，原进程与草稿保留；快捷入口已存在               | 保留现有控制器，不重新启动 Agent                                                 |
| 2. 拖入文件、检查、发送 | 完整绝对路径挤入正文，且可能与前一句粘连；需要编辑长路径才能移除 | `.14` 输入区显示文件名标签，完整路径可查看，支持独立移除和撤销；发送仍使用原路径 |
| 3. 找到更改             | “文件与成果”只打开文件树，把文件浏览误称为成果验收               | `.14` 分为“文件”和“查看更改”；复用原源代码控制面板，普通文件夹不展示 Git 审阅    |
| 4. 分屏后创建并行任务   | 分屏只是另开 Shell；创建工作区弹窗沿用当前项目                   | 保留并解释；回归检查项目继承与目标窗格，不自动创建或启动任务                     |

输入框增加拖入引用和发送／换行提示。附件错误使用状态提示供辅助技术读取。文件名重复时，移除按钮的可访问名称包含完整路径；键盘 Enter 移除引用不会发送消息。视觉截图不能证明完整无障碍合规，屏幕阅读器实测仍未执行。

## 后续功能的实现顺序

2026-09-20 最新范围调整：用户明确先做 Codex GUI，国内 CLI 暂缓。下面的近期能力核对与开发均以 Codex 为首个执行器；不并行推进国内 CLI 接口和转录适配。现有第三方入口、模型账户与八项入门继续保留。

| 优先级 | 用户操作                 | 开发要求与验收                                                                                                                                                                 |
| ------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 下一步 | 先描述任务，再选择在哪做 | 复用已有完整 composer；把目标作为主输入，项目／Agent／执行位置作为紧邻选项，分支和设置脚本逐步展开。现有快速创建弹窗仍以工作区名为入口，不将本轮入口修复称为已完成任务优先界面 |
| 已交付基础入口；队列后续 | 工作中补充一句话         | `.15` 提供 Codex 桥接会话的独立补充按钮，复用原 PTY；不将送入终端等同于已被模型执行。后续核验 Codex 的介入、排队与取消接口，再实现可编辑、可移除的待发送队列；失联时不能当作已发送。 |
| 下一步 | 看懂执行进度和待确认事项 | 复用现有工具活动／审批模型与执行主机状态；归纳活动、展开详情，给失败提供对应恢复动作；不从未采集的终端文字猜状态                                                               |
| 随后   | 预览产物并继续修改       | 文件预览、Git 更改、浏览器设计意见按产物类型进入同一任务反馈；Git 面板明确是整个工作区范围，任务专属产物需要真实关联记录                                                       |
| 随后   | 从飞书／企业微信开始工作 | 平台连接管理身份；具体来源、材料范围和回写目标显示在任务内。先浏览和选资料，写入外部系统时展示具体对象与权限。当前尚未实现平台级连接                                           |

国内 Agent 的 GUI 转录接入暂缓；模型 API 账户可保存不代表拥有相应 CLI 的完整图形会话。保留原八项入门清单和专业功能，不通过删除功能制造简洁。
