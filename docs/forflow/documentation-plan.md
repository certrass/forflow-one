# Forflow One 操作手册与帮助中心决定

日期：2026-09-19。依据：用户要求“然后操作手册你看看官网的doc决定一下”；当前应用 `1.4.205-forflow.6`，源码基线 `8503fb923b9509a117100adf125da309a60fb393`。本文是工程判断，不冒充用户逐项批准的产品需求。

## 决定

沿用 Orca 官方文档的「入门 → 工作流 → 功能参考 → 排障」结构，内容以 Forflow 当前版本重新编写。交付分为 [操作手册](user-manual.md) 和 [管理员手册](admin-manual.md)。网站层复用仓库已有的 MDX／Fumadocs 工程；下一步先接应用内的离线手册，再提供可自托管的帮助中心。

本轮交付两份 Markdown 手册、入口索引和这份改造依据。没有修改或发布文档站，没有给桌面增加帮助菜单入口，也没有重新打包应用。

## 哪些官网内容改变了判断

| 官网与源码证据                                                                                                                           | 判断及处理                                                                                               |
| ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| [文档目录](https://www.onorca.dev/docs) 按工作树、智能体、审阅、浏览器、终端、远程、自动化组织                                           | 适合研发团队；保留任务流程骨架，不按治理模块堆砌入门页                                                   |
| [首次三智能体会话](https://www.onorca.dev/docs/first-session) 以快速并行和提交 PR 为目标                                                 | Forflow 先完成一个小任务的本地闭环，再开第二个工作树；不把尚未认证的国内 CLI 写成开箱即用                |
| [会话历史](https://www.onorca.dev/docs/agents/session-history) 介绍已有执行器的发现与恢复                                                | 对照当前历史读取器逐项标记。新增菜单名称不能证明新增解析器；WorkBuddy／QoderWork 桌面与独立 CLI 分开说明 |
| [CLI](https://www.onorca.dev/docs/cli/overview) 和 [技能](https://www.onorca.dev/docs/cli/skills) 含上游命令与安装方法                   | 普通用户走 Forflow 随包 CLI／技能入口；保留技术 ID 的兼容含义，不照抄公共安装、分享步骤                  |
| [遥测](https://www.onorca.dev/docs/telemetry) 与云分享内容描述上游产品策略                                                               | 重写 Forflow 出站策略，分清产品遥测、本地诊断、模型请求和任意进程流量                                    |
| [远程服务器](https://www.onorca.dev/docs/remote-servers) 标注 Beta；[编排](https://www.onorca.dev/docs/cli/orchestration) 属进阶实验能力 | 移到管理员／进阶章节；远程令牌不等于用户授权，decision gate 不等于业务审批                               |
| 本地 `docs/site` 已包含 Next.js、MDX、导航、搜索和素材                                                                                   | 复用现有框架；不另建 CMS，也不把现有站直接当离线帮助交付                                                 |

官网是持续变化的上游说明。本轮读取的页面与仓库固定版本不必一致，个别历史支持列表、远程恢复表述需回到代码和实测判断；未逐条确认的上游承诺不直接迁入 Forflow 手册。

## 中文内容与栏目映射

| 帮助栏目                 | 用户要完成的事                                   | 内容来源和处理                                           |
| ------------------------ | ------------------------------------------------ | -------------------------------------------------------- |
| 开始使用                 | 安装正确版本，完成第一个任务，理解八项入门       | 重写 Forflow 安装、版本核对、本机模式；八项不删减        |
| 国内智能体与模型         | 找到产品，准备 CLI／认证／模型，判断历史是否可用 | 以国内接入代码和官方厂商资料为准，标明每层状态           |
| 项目与并行工作           | 添加仓库、起始分支、工作树、共享目录、清理       | 改写上游工作流，补充共享和删除的实际影响                 |
| 文件、终端、浏览器与审阅 | 修改、运行测试、看差异、提交、预览和上传         | 中文界面名称与当前设置对应；云产物分享从正常流程移除     |
| 账号、权限与隐私         | 分辨企业／模型／Git 账号和操作系统权限           | 按 Forflow 自有身份、上传确认和私有策略重写              |
| CLI、技能与自动化        | 注册命令、检查状态、调用能力、排查失败           | 先给经核对的常用路径，完整参数由当前 CLI schema 生成参考 |
| 管理与私有部署           | 部署身份、固定执行器、控制出站、备份和验收       | 独立管理员手册；明确客户环境尚未验收部分                 |
| 故障与版本说明           | 识别错误所在层，提供可复现信息                   | 每版更新已知问题、兼容条件、证据范围和升级回退           |

不把“无上游云登录”表述成“完全离线”，不把“国内品牌”表述成“全部国产依赖”，不把“通过测试”表述成“通过客户审查”。保留第三方产品真实名称、命令和版权归属。

## 文档工程怎么接

现有站是独立的 Next.js 应用，路径为 `/docs`，内容在 `docs/site/content/docs`，搜索使用 `/docs/api/search`，站点还含 OG 路由。它有自己的锁文件、Node 和 pnpm 版本要求，桌面依赖安装不会同时安装此站。版本目录虽有预留，目前没有可用的版本路由。

已确认需要改造的文件：

| 文件                                             | 要改的内容                                                                          |
| ------------------------------------------------ | ----------------------------------------------------------------------------------- |
| `docs/site/src/components/layout/DocsHeader.tsx` | Forflow 标识、中文导航、部署方链接；移除向 GitHub API 获取上游星数的服务端请求      |
| `docs/site/src/components/layout/DocsFooter.tsx` | 中文帮助与部署方支持入口，移除原社区导航；许可证声明独立保留                        |
| `docs/site/src/app/layout.tsx`                   | 页面语言、标题、图标、站点地址、分享元数据；私有部署默认不被搜索引擎收录            |
| `docs/site/content/docs`、`src/lib/source.ts`    | 通过明确的 Forflow 内容入口加载本站文档，避免混入上游功能承诺；保留上游文件用于追踪 |
| `docs/site/public/docs`                          | 现有 Forflow 素材和本版脱敏截图；重拍旧 Orca 界面，不靠替换图片说明遮盖旧图标       |
| 桌面帮助菜单与打包配置                           | 加入「操作手册」本地入口，随应用携带匹配版本内容；可配置内部在线帮助地址            |

内容只维护一个权威来源，网站与随包帮助从同一来源生成。按文章拆分时从 `docs/forflow` 迁移并保留链接，不形成两份人工维护的正文。每个发布快照记录应用版本、部署配置、源码提交、核验时间；帮助站新版本不能覆盖旧包说明。

离线帮助应打包文字、图标、截图和中文搜索索引；不让打开帮助触发外部字体、视频、CDN、统计或 GitHub 请求。现有站仍需依赖与网络审查，不能仅改成中文就宣称零外联。Next 服务端搜索不能直接复制到无服务的本地文件中，应提供静态搜索产物；首个最小版本可先有可离线阅读和页内查找，再接全文搜索。

## 本轮核验与发现

手册依据 `.6` 交付回执、29 个设置页面清单、八项引导渲染结果、身份服务说明、国内接入代码和官方文档编写。已在隔离配置下读取安装包 `forflow --help`、`worktree --help`、`terminal --help`，退出码均为 0。

**发现 CLI 帮助仍是英文且使用 Orca 品牌**，说明之前桌面中文验收不能扩展为整个 CLI 已汉化。本轮将其登记为下一版修复项，未修改 CLI 源码。原始输出留在本机 `.forflow/evidence/manual-cli-help/`。

本轮仅验证文档链接、结构与已有实现对应关系，不把此前应用回归结果登记为本轮新跑，也不把官网研究写成客户操作验收。
