# 连接引导与伙伴选择

## 本轮改动

连接页先回答三个问题：接入什么、现在是什么状态、下一步点哪里。常用操作留在主界面，安装命令、应用 ID 和断开操作在展开后显示。

- 「连接智能伙伴」按用途介绍豆包工作伙伴、WorkBuddy 和 Qoder 国内版，加入已有图标与重新检查入口。豆包模型配置单独收起，避免把模型服务与飞书伙伴当成同一种连接。
- 豆包工作伙伴提供名称列表。发现多个伙伴时需要明确选择；连接后仍使用标准新任务、智能体选择器和原生聊天。界面不发送测试消息。
- 飞书任务放到集成页首位。已有授权可直接连接；首次设置按安装工具、选择应用、登录授权三步展开。连接成功后主按钮为「查看任务」，应用 ID、刷新与断开放到「管理连接」。
- 配置错误给出对应动作；连接检查、进行中的操作和远程主机提示独立显示。

## 使用实际接口

伙伴列表复用现有 `forflowAily.status/discover/connect/disconnect`，没有新增聊天页。桌面 IPC 与 `forflow aily` 统一使用 `companionDirectory('aily')`，从而让设置中的选择与 CLI 打开的对话一致。旧的桌面专用配置文件保留在原位置；当前 CLI 使用的伙伴配置继续作为实际来源。

仅本机桌面展示伙伴选择，远程与 WSL 设置范围不读取本机伙伴身份。切换主机后忽略未完成的本机返回值。已打开的对话继续通过现有 `pinConnection` 检查伙伴是否改变。

飞书任务授权与飞书伙伴会话授权分别由各自现有接口确认。任务连接不代表消息机器人已经开通，也不新增 IM 自动回复。

## QoderWake 参考核对

2026-10-07 只读检查本机 QoderWake 0.1.7（build 27）与实际连接页面。应用的服务端为 Bun 打包程序，内含可读模块边界和路由标识；本轮提取接口路径与流程关系，未移植实现代码。

实际页面中，飞书连接默认展示扫码方式；手动凭据、聊天配对和回复设置进入后续层级。任务看板按进行中、需要操作、已结束显示状态。此次借鉴的是操作层次和按状态给出下一步的方式。

本地包中的接口分成三层：

| 层级     | 已发现的接口路径                                                                        | 前端含义             |
| -------- | --------------------------------------------------------------------------------------- | -------------------- |
| 平台连接 | `/api/channels`、`/api/channels/feishu/qr/start`、`/api/channels/feishu/qr/poll`        | 选择平台并完成授权   |
| 聊天配对 | `/api/channels/pairing/pending`、`/api/channels/pairing/approve`                        | 选择允许使用的聊天   |
| 任务指派 | `/api/channels/pairing/:pairingId/targets`、`/api/channels/pairing/:pairingId/at-waker` | 指定接收任务的 Waker |

这些是当前本机版本的接口线索，不是已联调的合作接口。若后续接入 QoderWake，连接页应依次显示「连接平台 → 选择聊天 → 指派伙伴」，完成最后一步后再显示自动回复状态。现有飞书任务页继续负责读取任务库。

参考截图与原始路径清单保留在本机缓存 `Library/Caches/Forflow One/design/connection-guidance-20261007`；授权二维码截图不进入仓库和发布附件。

## 验证

单元测试覆盖伙伴发现与选择、空列表、失败重试、断开、远程与 WSL 范围、飞书应用参数校验以及切换主机后的迟到响应。

`tests/forflow-packaged/connection-guidance.spec.ts` 通过隐藏 Electron 窗口与模拟官方 CLI 检查：按名称选伙伴后从标准聊天入口继续、设置与 CLI 共用连接、飞书授权错误恢复、进入任务列表，以及深色和窄窗口布局。模拟数据只用于运行验证和截图。
