# 豆包工作伙伴与 WorkBuddy

两种伙伴使用现有的「选择智能体 → 发任务 → 在当前对话看回复」流程。底层运行 CLI，复用原生聊天、任务标签、草稿和终端切换。`1.4.220-forflow.4` 的独立侧栏页面已移除，未安装。

## 使用

在工作区点击新标签页，搜索「豆包」「飞书」或「WorkBuddy」，选择对应智能体。连接完成后，在对话框输入任务并发送；也可以从新建任务页选择智能体启动。登录沿用各厂商 CLI 的现有账号。

- **豆包工作伙伴**：使用官方 `lark-cli`，继续飞书中个人智能伙伴的同一段单聊。默认发现唯一的个人伙伴；多个伙伴可在「设置 → 智能体 → 连接智能伙伴 → 豆包工作伙伴连接指引」中按名称选择；终端仍支持 `forflow aily --connect <飞书会话编号>`。同一伙伴一次只在一个任务中打开，避免不同工作区同时发送。输入 `/refresh` 查看后续消息，`/exit` 退出。
- **WorkBuddy**：调用桌面应用内置的 CLI，通过 ACP 创建当前工作区的独立会话，支持后续回复和 `--resume` 恢复。工具操作使用厂商权限选项，在原生聊天中选择；停止按钮发送会话取消。无需注册新的开放平台应用。

CLI 命令为 `forflow aily` 和 `forflow workbuddy`。`--prefill` 保留为未发送草稿，普通任务参数在 `--` 后传入。WorkBuddy 在 macOS 中查找 `/Applications` 或用户 Applications 目录下的安装；其他安装位置可设置 `FORFLOW_WORKBUDDY_CLI` 指向带 WorkBuddy 产品标识的厂商 CLI。

当前豆包适配文本和 CLI 返回的文本化内容；图片、附件上传和飞书交互卡片按钮尚未接入。豆包的停止只结束等待回复，已发送的飞书消息仍保留。原生聊天在能够读取本机记录的桌面工作区启用；SSH 或 WSL 不借用桌面账号和安装状态。

## 实现

新增智能体复用既有 PTY 启动、执行主机状态存储、会话标识、JSONL 读取和原生聊天界面，没有独立顶层页面。连接就绪前不展示可发送的输入框，避免启动过程中把任务写入普通 Shell。多行内容使用 bracketed paste 作为一条任务传送。

本机 CLI 通过 OSC 9999 发布状态和会话标识；服务端保留权威来源，恢复能力使用独立 capability 标记。每个会话有单写入锁；同批历史消息使用递增时间戳，保持对话顺序。豆包绑定 profile、用户和伙伴，并在发送前复核；账号凭据由官方 CLI 管理。WorkBuddy 使用厂商登录，不读取或搬移登录密钥。

登录 Shell 会重新排序 PATH，因此 Forflow 的 zsh／bash 启动脚本在用户配置加载后恢复当前应用的 CLI 路径，避免候选包调用旧安装版。中英文名称和搜索别名使用现有目录，停止使用单独 aily 页面。
