# 飞书智能伙伴接入

用户选择先接飞书里的豆包工作伙伴（aily），在 Forflow One 内直接发任务、查看回复。

## 使用

侧栏打开「豆包工作伙伴」，点击「连接我的智能伙伴」。程序使用本机官方 `lark-cli` 的现有个人登录，查找专属智能伙伴；有多个时由用户选择。连接后同步同一飞书单聊，可查看历史、加载更早的消息、发送文本任务和阅读 Markdown 回复。「在飞书中打开」返回同一段对话。

草稿随页面切换保留。发送失败保留原文，同页重试复用消息幂等键。只在页面打开时轮询回复，不自动发送。连接文件仅记录应用、账号和伙伴标识，凭据由官方 CLI 管理。

## 路线与真实验证

2026-10-06，官方 CLI `1.0.84` 的现有授权已完成真实收发。`aily/v1/sessions` 需要额外的 `aily:session:write` 权限；本实现复用已可用的飞书 IM 个人消息接口，不依赖新建开放平台应用。

同名「豆包工作伙伴」账号实际是产品通知号；先前向它发送的单条无操作测试没有得到回复。用户专属的「某某的智能伙伴」是实际对话入口，已返回连接测试标记。发现逻辑排除通知号与群聊，只接受单个个人伙伴机器人。当前按默认个人伙伴名称发现，重命名后的伙伴和团队自建 aily 应用不在首版范围。

测试内容均为无工具操作的合成消息。真实会话 ID、消息 ID 和本地协议回执仅留在忽略目录 `.forflow/evidence/aily-local-20261006/`，不提交账号数据。

## 实现

- 复用飞书任务连接的 CLI 执行、账号核对和错误处理；保留原有任务权限校验。
- 主进程验证私有版主窗口、连接账号和固定伙伴。命令使用 argv 执行，通过官方 CLI 的幂等键发送，不拼接 Shell。
- 回复复用原生聊天的消息与 Markdown 组件；支持文本收发，飞书卡片采用 CLI 提供的文本表示。图片、附件上传及交互卡片按钮后续另接。
- 这是桌面飞书账号的对话入口。不会把本机的连接状态当成 SSH／WSL 执行器，也不改变配对运行时的视图协议。

## 验证与交付

定向单元测试已覆盖发现、账号切换阻止发送、仅读取绑定双方消息、字面参数、稳定重试键、持久绑定、受信 IPC、重复点击及原有飞书任务回归。成品测试使用独立 HOME 与隐藏 Electron 窗口检查入口、历史、草稿、收发与页面重载；截图采用模拟数据。完整回归 340 文件／3,560 项和 11 项身份服务测试通过；16,680 个中英文词条、全部工程类型与改动行检查通过。初轮旧审阅测试使用改版前的名称和自动教学行为，已改为真实的「修改材料 → 操作提示」，保留原有切页与关闭断言。

原有飞书任务成品场景的模拟 Codex 会话会主动生成用户消息，并通过 `.first()` 定位到隐藏工作区的输入框，导致未发送草稿断言失败。现改为新会话不生成用户消息、精确定位可见工作区，任务读取、分页、编辑和未发送草稿复验通过；未改生产聊天逻辑。

成品界面真实发送并收到 `界面连接成功 FFO-AILY-UI-04`。截图为模拟材料，未上传真实聊天记录。小窗口检查发现浮动终端按钮遮住发送按钮，已在 aily 页面隐藏该悬浮入口；全局快捷键保持原有行为。

候选为 `1.4.220-forflow.4`；详细哈希与最终复验位于 `~/Library/Caches/Forflow One/builds/1.4.220-forflow.4/qa/`。当前安装仍为 `.3`，等待用户保存退出后替换。
