# Forflow One 操作手册

适用版本：**1.4.205-forflow.12 · cn-private · macOS Apple Silicon 本机测试版**。更新日期：2026-09-20。面向团队及客户的 AI／研发人员。其他系统、真实国内模型调用和客户部署需分别验收。

本手册按当前 Forflow 界面、源码和本版安装包验证编写，参考 [Orca 官方文档](https://www.onorca.dev/docs) 的工作流结构。上游网页可能随版本变化；遇到差异，以本版说明和管理员配置为准。部署人员请看 [管理员手册](admin-manual.md)，开发人员请看 [工程文档索引](README.md)。

## 1. 先知道三个区别

| 名称        | 用来做什么                                     | 需要另行准备什么                       |
| ----------- | ---------------------------------------------- | -------------------------------------- |
| Forflow One | 组织项目、工作树、终端、文件、浏览器和差异审阅 | 本机应用；团队账号按需配置             |
| 智能体 CLI  | 在所选主机上实际读取文件、执行命令、修改项目   | 对应 CLI、厂商或企业认证、执行权限     |
| 模型服务    | 为智能体提供推理能力，如国内 API、客户内网模型 | 获准使用的模型地址、模型名、凭据与网络 |

Forflow 企业账号、智能体厂商账号和 Git 仓库账号分别配置。登录其中一个，不会自动获得另外两个的权限。当前企业账号管理成员与登录会话，尚未把成员角色接入工作区或数据权限。

一个项目可以有多个工作树。工作树是同一 Git 仓库的不同工作目录，通常各有分支，适合并行修改；它不等于操作系统沙箱，共享目录、环境变量和外部服务仍可能相互影响。

## 2. 打开正确的应用

1. 从「应用程序」打开 **Forflow One.app**。本次安装位置是 `/Applications/Forflow One.app`，原 Orca 应用单独保留。
2. 在应用的「关于」窗口确认版本为 `1.4.205-forflow.11`。旧下载包、开发版和 Dock 中的旧快捷方式可能打开不同副本。
3. 进入「设置 → 入门清单」。保留的清单包括 **6 项设置、2 项里程碑**；下方的私有部署说明是补充内容。
4. 只使用本机项目时可保持「本机模式」。团队提供账号服务时，再按第 5 节连接。

可从应用内「帮助 → 产品介绍」查看工作区、任务、智能体、工作台和代码审阅，也可使用系统菜单「帮助 → 探索 Forflow One」。完整八项入门仍在原入口，介绍浏览不会代替设置操作。

这是内部测试包，采用本机签名，尚未完成正式分发公证。系统拒绝打开时，把准确错误和包版本交给管理员核验；不要关闭全系统安全检查来绕过问题。

## 3. 完成第一个工作流程

先在测试仓库完成「打开项目 → 新工作树 → 修改 → 测试 → 审阅」。尚未配置模型时，可以用普通终端和编辑器完成同样流程。

### 3.1 添加项目

在左侧项目栏的添加入口选择本机已有 Git 仓库；如果需要克隆，先确认仓库地址、执行主机和 Git 访问权限。打开项目后，核对路径和默认起始分支。

本工程的推送仓库是 `certrass/forflow-one`；`stablyai/orca` 是上游来源。其他项目应使用各自所属的仓库，不能套用本工程地址。

### 3.2 新建一个工作树

在项目旁的「＋」入口创建工作区，填写任务名称，确认项目、运行主机和起始分支，再选择智能体或空白终端。需要明确分支名时，展开高级选项填写。

提交后等待后台准备完成。若失败，先查看错误：起始分支不存在、网络不可达、目录冲突和权限不足需要分别处理。不要为重试直接删除原项目。

新的工作树通常没有未跟踪的依赖、缓存和环境文件。先按项目自己的说明安装依赖。仓库中的 `orca.yaml`、`.worktreeinclude` 等兼容配置名称仍有效，不要自行改名；共享或复制密钥文件前先核对该任务是否有权使用。

### 3.3 开始任务

已准备好智能体时，选择对应 CLI，先确认终端显示正常认证和可用状态，再给出范围清楚的小任务。例如：

> 阅读这个测试项目的 README，提出一处说明改进。先说明要改什么，获准后只修改这个文件；不要提交或推送。

没有可用 CLI 时，选择空白终端，手动编辑测试文件。缺少国内 CLI 时，当前版本不会自动改用其他厂商。

若智能体请求命令、文件或网络权限，阅读具体动作后决定。Forflow 的默认启动参数保留执行器权限确认，但具体提示和效果还取决于厂商 CLI 版本。

### 3.4 验证与审阅

打开文件和差异视图，核对修改是否符合任务范围。在该工作树终端运行项目要求的测试，记录实际结果；智能体说“已完成”不等于测试已通过。

需要修订时，将具体文件、行或差异反馈给智能体。准备提交时，在源代码控制面板暂存所需文件并填写提交说明。首次测试可以停在本地审阅，不必推送。

确需推送时，先核对远程仓库、分支、将发送的文件和仓库权限。提交钩子失败时先处理错误；不要跳过钩子或使用强制推送来掩盖失败。创建 PR／MR 还依赖对应托管平台的认证与适配。

### 3.5 再做并行任务

从同一项目再建第二个工作树，为它指定另一个任务或比较方案。在两个工作树间切换，或分屏查看终端、文件和浏览器，分别检查分支和结果。

开发服务使用不同端口；不要让两项任务同时修改共享依赖或同一个外部数据库。清理前先检查未提交文件、未合并提交和运行进程。删除工作树会涉及实际目录；按确认窗口逐项核对，不把它当成仅关闭标签页。

本机已完成一个真实范例：左侧项目 `parallel-board-20260919`，工作树 `qa-ui` 与 `qa-logic` 分别承担中文任务板界面和任务数据逻辑。两个 Codex 会话均以 `gpt-6-astra`、`medium` 启动，运行时间重叠；各自仅提交约定文件，合并后 9 项测试通过。可以参照以下分工：

1. 先在共同起点写清接口、文件归属和验收，再创建两个工作树。
2. A 只改 `index.html`、`app.css`、`app.js`；B 只改 `tasks.js`、`tasks.test.js`。各自运行检查并审阅本地提交。
3. 审阅两边差异，再在集成分支合并并重新运行 `npm test`。本轮合并使用本地 Git；产品内合并按钮仍需单独验收。
4. 在内置浏览器检查添加、完成、筛选、删除与刷新后的状态。本机范例服务地址为 `http://127.0.0.1:55078`，仅在服务进程运行时可访问。

这次范例使用已有 Codex 登录，不代表国内模型 API 或不同厂商的协作已经联调通过。逐项记录见[官方功能实际验收矩阵](official-feature-results-20260919.md)。

### 3.6 自动化时区与旧计划

本轮确认 `.8` 保存的时区没有用于计算下次执行时间；`.9` 修复候选已把保存时区接入创建、修改、调度推进和补跑时间计算，编辑名称或正文也会保留原有时区。升级后，需要立即纠正的旧计划应重新保存一次时区或规则，以重新计算下次时间。本版没有批量迁移已保存计划的缓存时间。

仅设置了计划不代表智能体已经执行。本轮时区检查全程使用停用的测试计划，验证后删除；真实定时触发、远程主机运行和模型结果需要另行验收。

## 4. 八项入门清单怎么完成

清单进度按应用检测到的条件更新。读完手册不会自动完成一项；下面同时给出可观察的检查结果。

| 清单项目                   | 操作与检查                                                                                                                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 开启通知                | 从清单进入通知设置，按需允许系统通知；清单完成仅表示应用内通知开关已开启，macOS 通知权限与实际送达需在详情中分别检查。勿把手机推送当成已启用能力。 |
| 2. 选择默认智能体          | 在「设置 → 智能体」选择已准备好的执行器；新建工作区时检查预选项。仅选中名称不会安装或认证 CLI。                                                    |
| 3. 启用 Forflow One CLI    | 打开该项，选择「安装 CLI 和技能」，完成本机命令注册及随包技能安装；重新打开终端检查 `command -v forflow`。                                         |
| 4. 连接集成服务            | 在「设置 → 集成」连接团队实际使用的服务，检查认证及仓库访问。没有获准使用的集成时可暂留未完成，不必为凑满进度开通外部服务。                        |
| 5. 自动配置工作区          | 为测试项目配置初始化命令，再创建一个测试工作树核对结果。自动脚本会执行真实命令，先阅读项目配置。                                                   |
| 6. 在多个仓库中开始工作    | 添加第二个获准使用的仓库，分别打开并确认路径、主机和分支。                                                                                         |
| 7. 多任务并行              | 同时在两个不同工作树开展工作，分别检查任务及修改；不要重复使用同一工作目录。                                                                       |
| 8. 使用 Forflow One 浏览器 | 在工作树内打开浏览器访问测试页面，验证刷新、页面查看及需要时的元素反馈。                                                                           |

「启用 CLI」中的智能体编排、浏览器使用和计算机控制，说明随包技能的用途；安装技能不会自动授予系统权限，也不表示每个国内执行器已完成技能联调。「完全磁盘访问权限」按需要授予，普通项目操作不以全量授权为前提。

## 5. 本机模式与 Forflow 企业账号

本机模式可以使用当前操作系统用户有权访问的项目。若团队部署了自有身份服务：

1. 打开「设置 → Forflow 企业账号」。
2. 填入管理员提供的 **HTTPS 服务地址**，保存并检测；本机调试服务可用回环 HTTP 地址。
3. 使用管理员分配的账号和密码登录。该页面连接配置的 Forflow 服务，不使用 Orca 云账号登录。
4. 退出时撤销当前身份会话；账号被停用或重置密码后，需要重新登录。切换本机模式不会自动停止已启动的外部智能体进程。

只有管理员能看到成员管理入口。界面中的「AI 提供商账户」属于另一类账户设置，不能用于建立 Forflow 企业成员。当前没有企业 SSO 跳转，后续再接入。

## 6. 国内模型与智能体怎么找

打开「设置 → 智能体 → 国内模型与智能体」。也可从右侧「智能体会话历史」的查看选项，点击顶部国内产品入口进入这里。

| 希望使用的产品         | 当前接入路径                                                | 本版能力与下一步                                                                                   |
| ---------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 豆包／火山方舟         | 在适用执行器配置获准的模型；`arkcli` 属于模型及工具命令路线 | 提供接入导航；尚无 Forflow 内模型配置向导或独立历史读取器，真实调用待联调                          |
| WorkBuddy／CodeBuddy   | 独立 `codebuddy` CLI                                        | 已实现命令检测、交互启动参数与进程识别；WorkBuddy 桌面账号、历史不会自动导入，真实登录后任务待验证 |
| QoderWork／Qoder CN    | 国内 `qodercn` CLI                                          | 已有国内 CLI 启动适配；QoderWork 桌面账号和历史不会自动导入，真实执行与历史恢复待验证              |
| TRAE CN、Qwen、Kimi 等 | 对应执行器目录和实际 CLI                                    | 保留现有适配；安装、认证、模型地域和费用需要分别确认                                               |

界面检测的是**实际执行主机**：在 Mac 上装好 CLI，不代表 SSH 主机也已安装；“检测失败”也不能当成“未安装”。安装和登录采用厂商官方步骤，由管理员按需固定版本。详见 [国内 CLI 接入说明及官方链接](domestic-cli.md)。

从 `.10` 起，「设置 → AI 提供商账户」支持 Kimi、智谱 GLM 和 DeepSeek 官方 API Key 的本机加密保存、修改、移除和显式连接测试。使用开放平台 API 额度，网页会员及 Coding Plan 另行配置；暂不自动改写 CLI 登录。具体步骤见 [国内模型 API 账户](model-accounts.md)。

若设置国内或内网模型，需要确认执行器支持的协议、地址、模型名和凭据配置方式；Forflow 企业账号页面不是模型密钥入口。不要把 API 密钥贴入任务对话、截图或仓库。开发环境预留的模型配置由负责人本机管理，不属于普通用户安装步骤。

### 为什么历史里没有国内产品的勾选项

历史列表需要专门读取各执行器的会话文件。当前三项国内入口是**接入导航**，并显示「模型／工具接入」或「历史暂未接入」；不是可用的历史筛选器。

启动一个 CLI、看到终端记录、导入会话历史、恢复对话是不同能力。CodeBuddy／Qoder CN 的历史解析尚未实现，不要通过复制其他产品的历史文件来“补齐”。

## 7. 文件、浏览器和上传

文件面板用于打开、编辑和查看工作树中的文件；Markdown 等产物可在本机预览。浏览器标签随工作树组织，适合打开该任务的本地开发页面或团队允许访问的网站。

上传之前先核对文件和目标网站。Forflow 提供的文件上传路径有确认步骤：取消应不发送文件，允许后才将所选内容交给目标。相机、麦克风、剪贴板等网站权限也需核对请求来源；页面跳转后可能需要重新授权。

智能体通过终端、独立 CLI、MCP 或其他工具发送文件，不一定经过浏览器上传确认。客户数据的访问范围和出站限制需由管理员在执行环境另行配置。

远程工作区还需核对浏览器工具栏的主机信息、文件选取位置及上传暂存位置；本版上传字节验证覆盖本机流程，尚未验证所有远程传输组合。Orca 云产物分享在私有版被阻断，需要交付时使用团队批准的文件或文档渠道。

## 8. CLI、技能与自动化

从入门清单安装后，可用以下只读检查确认入口：

```sh
command -v forflow
forflow --help
forflow worktree --help
forflow terminal --help
```

如果找不到命令，查看安装结果显示的位置，重新打开终端并检查该位置是否在 PATH 中。不要自行注册成 `orca`，以免调用原应用。

**从 `.12` 起：**命令入口、帮助示例、错误恢复建议和技能指令使用 `forflow`；根帮助和 234 条命令简介为中文。`forflow skills get forflow-cli` 读取当前安装包的指南，旧 `orca-cli` 主题仍作为兼容别名。详细选项说明和长篇技术参考仍有英文，不能据此宣称整个 CLI 已全量汉化。

技能安装也可离线执行：

```sh
forflow skills install --all --dry-run --json
forflow skills install --skill forflow-cli --skill orchestration --json
forflow skills install --skill forflow-cli --agent claude-code,codex --json
forflow skills update --all --json
```

默认使用共享的 `~/.agents/skills`，`--local` 使用当前项目目录。现有 `orca-cli` 等技能目录保留，以保护已安装内容和本地修改；对外指南名称映射为 `forflow-cli` 等。更新只处理已安装技能，冲突时保留原文件并返回失败状态。SSH 转发入口不能在错误的主机上执行技能安装，应在目标机器直接运行。

`FORFLOW_USER_DATA_PATH`、`FORFLOW_ENVIRONMENT`、`FORFLOW_PAIRING_CODE`、`FORFLOW_APP_EXECUTABLE` 可配置数据目录、远程环境、配对码和应用程序；与对应的 `ORCA_*` 兼容变量同时存在时，前者优先。机器字段、远程配对协议及执行主机的权限语义保持兼容。云分享仍默认关闭。

`forflow account` 管理 Claude/Codex 托管登录；Kimi、智谱、DeepSeek 的 API Key 在应用“AI 提供商账户”中配置，两者不是同一账号接口。

技能优先从清单安装随包版本。不要直接照抄官网依赖公共注册表的安装命令。编排属于进阶能力，先在测试仓库验证工具调用、等待、取消和恢复；它的决策阻塞点不是企业业务审批。

「设置 → 自动化」可用于配置定时任务。启用前核对任务文本、运行主机、项目和模型授权，并先执行一次人工试跑。服务是否在线、机器是否休眠和账号是否过期都会影响结果；本版未做客户环境无人值守验收。

## 9. 权限遇到问题怎么处理

| 现象                             | 检查位置                                                                |
| -------------------------------- | ----------------------------------------------------------------------- |
| 无法操作系统界面                 | 「设置 → 计算机控制」及「macOS 权限」；检查辅助功能等必要权限           |
| 无法读取屏幕                     | macOS 对 Forflow 及其权限助手的录屏授权；根据系统提示重新打开应用后复测 |
| 特定受保护文件夹无法读取         | 先核对目录与当前用户权限，确有需要再开完全磁盘访问                      |
| 网站无法用摄像头、麦克风或剪贴板 | 核对网站来源、浏览器确认和对应系统权限                                  |
| CLI 自己拒绝读写或执行           | 检查该 CLI 的权限请求、执行用户和工作目录                               |
| 企业账号能登录但项目打不开       | 企业身份与本地文件权限独立；检查 OS、SSH 或 Git 权限                    |

安装新版本或权限助手身份变化后，系统权限可能需要重新识别。不要把设置页面的开关状态当成实际功能已经生效，应做一次最小操作确认。

## 10. 常见故障

| 问题                   | 处理顺序                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------- |
| 仍见旧图标、旧文案     | 先确认应用路径和「关于」版本，退出多余副本；记录具体页面和截图，不先归因于缓存      |
| CLI 状态无权限读取     | 查看中文错误并检查命令路径访问权限，修复后点击刷新；状态未知时不会执行注册或卸载    |
| CLI 未检测到           | 确认所选主机，再在同一主机终端核对命令、PATH 和版本；桌面产品已安装不能代替独立 CLI |
| CLI 已找到但任务失败   | 查看 CLI 自身认证、模型地址和权限错误；不要反复重装 Forflow                         |
| 没有历史或恢复失败     | 检查历史来源是否已支持、主机和筛选是否正确；国内接入导航不产生历史读取能力          |
| 创建工作树失败         | 核对起始分支、目标路径、Git 状态、主机连接；只清理已确认无用的测试目录              |
| 推送返回 403           | 核对仓库所有者、远程地址和当前 Git 身份；本工程应推送 `certrass/forflow-one`        |
| 企业登录失败           | 检查服务地址、证书、连接检测、账号状态和密码；管理员检查服务健康与身份审计          |
| 私有版分享或更新被拒绝 | 当前按私有策略阻断，联系管理员采用内部交付流程                                      |
| 远程连接中断           | 先恢复连接并查询远端进程；断开不代表任务已终止，不要直接重复启动同一任务            |

如果 CLI 状态提示没有权限读取命令路径，请让管理员核对 `/usr/local/bin/forflow` 的所有者、符号链接权限和实际目标。此前本机旧链接由 root 所有、权限为 `0700`，普通用户无法读取；`.8` 已修复后续管理员安装创建此类链接的问题，但不会自动覆盖旧链接。2026-09-20 已在系统授权后核对目标并将本机链接修复为 `0755`，实际命令和应用刷新均正常。其他机器应先确认目标确为 Forflow One 内置启动器，再修复符号链接自身的可读权限；无法确认目标时先保留。
