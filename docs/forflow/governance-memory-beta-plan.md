# Forflow One：记忆接续、审计与资产 Beta 增量规划

2026-09-20。以本仓库 `.17` 为观察起点；首个增量是「接续预检」。范围是团队／客户 AI 与研发人员的 Codex 工作台，不重写编排，不引入完整 Ontology，不把未验证的治理能力写成合规认证。

## 本轮决定与实物

用户要求：系统规划后做小功能，纳入 Beta，避免大改；重点检查多 Agent 的记忆承接、提取、污染、损耗和低打扰体验。

首个实现为 **B0 接续预检**：设置 → 实验性功能中默认关闭；启用后，在 Codex 对话上方按需提取当前已加载记录，预览整条用户原文与最多三条近期 Agent 答复。显示来源、遗漏类别和 UTF-8 字节预算，可显式复制带内容指纹的 JSON 回执。会话变化、执行中、历史未加载完整或用户文本超出预算时禁止复制。它不调用模型、不存长期记忆、不自动向其他 Agent 发送。用户仍通过原输入框决定目标和发送内容。

这是自动交接前的观察阶段，不是自动提取业务事实、长期记忆服务或完整审计归档。窗口复制也不构成接收 Agent 已读取的证明。实际验证结果见 [本版发布记录](release-1.4.205-forflow.18.md)，使用方法见 [接续预检说明](context-handoff-beta.md)。

## 现有机制：哪些可沿用，哪里会损耗

| 当前源码接点 | 已有机制 | 本轮判断与缺口 |
| --- | --- | --- |
| `src/main/runtime/orchestration/db/tasks/task-store.ts` | 任务、依赖和父任务归属于 Run，创建时校验同 Run | 有可靠结构基础；Run 边界不是企业租户／部门授权 |
| `orchestration/preamble.ts` | 下发任务说明、通信方法、任务及分派标识，要求结果摘要 | 指令明确，但短摘要可能丢约束、反证及失败原因；不能据此恢复所有业务上下文 |
| `coordinator-task-dispatch.ts` | 自动分派带当前任务说明和最近一次已解决决策门结果 | 它不是所有约束／批准的完整账本；业务授权不能仅存在摘要里 |
| `rpc/methods/orchestration/runs/dispatch-methods.ts` | dry-run、指定分派、读取分派；展示 preamble 可从当前说明重建 | 重建结果不是不可变的历史发送副本；后续审计应记录实际发送版本 |
| `db/attempt-observation-types.ts` | 执行、产物、工作者报告、协调者确认、存活与未知分别建模 | 已经有区分陈述与观察的基础，不能另造“模型说完成 = 已验收”的状态 |
| `src/shared/native-chat-types.ts` 和会话读取器 | transcript／hook／scrape 有来源及优先级，支持分段历史 | 当前 GUI 可见记录不是厂商完整模型请求，也未必覆盖子 Agent、工具内部上下文和压缩前历史 |
| `docs/forflow/data-and-evidence.md` | 已有十二段数据链、事件与资产合同设计 | 是设计，尚非企业权限、独立审计存储及 Q2Q 跨服务联调完成证据 |

关键损耗有六类：

1. **语义损耗**：逐级摘要删掉否定、条件、反证、责任人或未解决问题。摘要再摘要会放大偏差。
2. **范围污染**：跨项目、跨客户、跨角色召回了看似相似但不适用的记录；向量命中不代表有权使用。
3. **证据漂移**：Agent 自述被重新包装成事实，旧文件／旧批准被当作当前版本，接续时拿不到原来源。
4. **控制污染**：资料中嵌入的指令被当成上游任务；同 Run／共享工作区被误解为继承人的权限。
5. **过程损耗**：只保留成功总结，丢掉失败尝试、状态未知、重试和接口副作用。恢复后可能重复执行。
6. **成本损耗**：重复回灌完整历史，或每轮都做 LLM 总结、全库向量检索和全群广播；局部省 Token，整体反而更贵。

不承诺无损压缩。对必须准确的条件，保留原文或结构字段；对可压缩的探索过程，保留可按需打开的来源。B0 因无法判断哪句话是强约束，暂保留全部可用用户文本；超过预算时停在预览。旧限制与新纠正仍按顺序呈现，当前算法不会自动裁决哪条失效。

## 目标：四层分开，按需装配

| 层 | 权威对象 | 使用与更新规则 |
| --- | --- | --- |
| 执行事实 | Run／Task／Attempt、消息、源事件、实际请求与回执 | 执行主机负责；断联是 `unverifiable`，不能推成 `exited`。原始事件不能由摘要覆盖 |
| 任务工作记忆 | 目标、约束、已确认决定、未决问题、下一步、产物引用 | 绑定项目、任务、版本及有效期；恢复或交接时重取现状，不重放副作用 |
| 可复用候选 | 经验、失败原因、纠错案例、Skill／规则修改建议 | 自动提取可在后台进行；每条保留原文引用、提取器版本和适用条件，不能直接写正式规则 |
| 获准知识与资产 | 发布的规则／Skill／数据快照／决策函数／评测集 | Q2Q 复核具体版本，支持替代、撤回和复评；读取时校验当前权限与撤回状态 |

任务接续包按三部分构造：①当前任务合同的关键字段和原文；②当前任务相关的来源片段与结论、反证；③只给引用的详细轨迹、文件与旧讨论。缺少关键合同就补齐或请求有限澄清，不能用召回结果猜授权。

同任务重复请求使用 `task + attempt + source revisions + policy revision + recipient scope` 作缓存键。缓存命中仍重新验证权限、有效期、来源撤回与接收方；向量库只作候选索引，正式来源和授权判断不能靠索引标签代替。

### 无感的实现范围

- 自动：关联已存在的任务／会话 ID、记录源版本、去重、标记压缩／缺失、构建候选、按任务范围检索、计算已观察用量、保留断点。
- 轻提示：会话顶部一句“已带入 4 条资料／有 1 条过期”，点击展开来源；正常情况不弹窗，不要求用户填写完整交接表。
- 需要用户判断的少数情况：目标冲突、关键约束缺失、读权限变化、资产正式晋升、外部分享或业务动作超出已有授权。
- 后台任务有幂等键、超时与预算；无新事件不重跑提取。普通执行不能因可选记忆服务故障假装失败，也不能把证据缺口抹成完整。

**低打扰不等于静默扩大采集。** 首次选择 Beta 范围后，在既定范围自动完成；读不到的数据和厂商未披露的内容保持“未获取”。摘要、嵌入及推导内容继承源的敏感级别、用途、保留期限和撤回关系。

## 小步发布顺序

| 增量 | 有限交付 | 通过什么再扩围 | 回退 |
| --- | --- | --- | --- |
| B0 接续预检（本轮） | Codex GUI 中原文摘录、来源清单、缺失提示、预算、显式复制 | 来源正确、关键原文不被截断、跨窗格不串、缺失阻止复制；不发送、不改状态 | 关闭设置即隐藏入口，不改现有会话 |
| B1 任务接续合同 | 为 Forflow 正式分派保存目标／约束／来源快照，准备、发送、接收回执分别记账 | 断网／重试不重复执行；实际接收包与冻结版本一致；撤权／撤回立即失效；新旧客户端兼容 | 回到原分派，不删除历史回执；不支持的远端明确降级 |
| B2 候选记忆提取 | 任务完成或被纠正时后台提候选；沿用 Q2Q 的证据／判断接口 | 合成与真实许可案例中测原文支持率、关键条件遗漏、冲突、错误晋升；禁止自行改评测集 | 停止提取，保留候选历史，正式规则不受影响 |
| B3 资产与审计 Beta | 文件／报告／Skill 版本登记，Owner、适用范围、依赖、评估；追加事件存储与受控导出 | 源版可回读、权限真实拒绝、故障缺口可对账、恢复与删除可验 | 停止新增接入，已存事件继续可读 |
| B4 用量与复核看板 | 项目／任务成本、缺口、待业务复核与异常分诊；少量只读共享 | Token 去重、缓存／重试／子任务计费核对；看板每项可下钻，未知不计零 | 关闭视图／连接器，不改变任务运行状态 |

每个增量单独开关与验收。不要先安装 Pydantic AI、FastMCP、MLflow、OPA、OpenMetadata 等完整组合。B0 沿用 TypeScript 和当前会话结构；B1 先复用现有持久化、分派与消息机制，再决定独立服务的边界。

## 任务看板、Q2Q 与资产怎么接

保留三条独立状态轴：

- 执行：待执行／运行／阻塞／成功报告／失败／状态未知，沿用执行主机状态源。
- 证据：待采集／部分／可核对／存在缺口。不能由任务“完成”自动推成证据完整。
- 业务复核：未提交／待复核／需修改／获准指定版本／已撤回。获准产物改变后必须重新判定。

现有“已完成”列不立即改语义。B4 先增加筛选或辅助标签，并给旧数据标明来源；无明确业务复核记录时显示“未复核”。不为了界面整齐把未知补成通过。

轻量资产合同：`asset_id, version, kind, owner, scope, source_refs, content_hash, classification, policy_ref, evaluation_ref, status`。依赖先用 `derived_from / consumes / produces / supersedes / evaluated_by / approved_by`。表格增加字段类型、单位、统计期间、主键、质量约束；普通关系表即可承接，暂不做全企业语义推理。

Q2Q 收到的是“判断候选＋原文位置＋证据版本＋反证／缺失＋规则版本”，不是无来源的分数。类型正确只解决格式，不保证事实正确；模型自己报的 confidence 不当作已校准概率。需独立标注、留出集、校准曲线和弃判成本后再决定阈值。

## 如何度量收益与损耗

在同一批任务上比较：全历史传递、现有短摘要、原文引用包、候选提取后引用包。任务、输入版本、模型及验收固定，不能边调提示边改标准。

| 指标 | 计算与验收 |
| --- | --- |
| 关键约束保留 | 对具名测试案例逐项检查禁止动作、范围、版本、未决问题；任何严重约束遗漏应阻断晋级 |
| 原文支持与纠错 | 随机抽取候选回读支持片段；撤回／修正后测旧记忆是否仍被召回或进入请求 |
| 污染与授权 | 跨项目／跨人／带注入的工具输出测试；校验服务端拒绝，不仅是 UI 隐藏 |
| 全任务成本 | 汇总主／子 Agent 的实际 input、cached input、output、重试、压缩、提取与检索成本；价格版本和币种分别记 |
| 延迟与打扰 | 接续准备 p50/p95、重取资料次数、人工澄清次数、任务重做率；不只测摘要生成时间 |
| 证据完整性 | 已提供、已读取、实际请求纳入、结果引用四种事件分别核对；上游不可见时无完整率分母 |

B0 显示字节数和遗漏数，**不把字节压缩率写成 Token 节省率**。零额外模型调用只指预览提取本身；复制给下一 Agent 后的调用仍会产生费用。本轮不宣称已测得质量提升或实际 Token 节省。

## OpenSharing 与大陆审计要求

已定位 [OpenSharing 官方仓库](https://github.com/OpenSharing-IO/OpenSharing)；其 README 当前说明现有连接器支持表共享，Volume、Model、AgentSkill 连接器仍在推进。先列为 B4 的表共享互操作验证对象，不作为 B0 依赖。完整 Ontology 暂缓，字段口径和轻量依赖保留。[Linux Foundation 公告](https://www.linuxfoundation.org/press/linux-foundation-announces-opensharing-project-to-standardize-ai-asset-and-data-exchange)

临时凭据／直读存储不能代替审计。后续需关联授权决定、凭据签发、存储侧实际访问与撤销；零拷贝也不代表接收方从未读到或缓存数据，已发出的临时凭据和已下载副本不能靠关闭 UI 撤回。

[公安部第176号令官方转载全文](https://gaj.linxia.gov.cn/gaj/gaxw/gsgg/art/2026/art_5f125ac64d52498d9a50ffe4f2407bd5.html) 第23条规定 2026-10-01 施行；本记录日期仍在施行前。第7条的检查涉及安全制度、日志及技术措施、风险整改、数据安全与个人信息义务；第12条涉及检查材料和技术措施；第16—19条涉及风险处置与整改。平台应支持履责和可核对材料，但该办法不是单一软件的“认证清单”。

本计划的工程映射是：账号与权限 → 每次对象访问的决定；数据源／资产版本 → 可回读的来源；事件链 → 实际运行证据；异常分诊 → 整改及复测。完整适用义务仍取决于客户系统、行业、数据和部署，B0 的本机 JSON 指纹不是独立审计存储，也不能证明“已符合176号令”。保留期限按记录类别和适用义务确定，不能统一随会话清理。

## 研究依据与未决事项

- [Databricks Memory Scaling](https://www.databricks.com/blog/memory-scaling-ai-agents)：强调质量、过时、访问范围及蒸馏后的敏感性。本轮采用来源与撤回优先、候选与正式知识分离，不套用其实验提升百分比。
- [AWS Bedrock 多 Agent 配置](https://docs.aws.amazon.com/bedrock/latest/userguide/create-multi-agent-collaboration.html)：历史转发是可选配置；不能认为开启多 Agent 就自动得到完整正确的接续。
- [AWS AgentCore 记忆类型](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/memory-types.html)：短期事件和长期提取不同，支持分层规划；本轮未部署 AWS 服务。
- 本地白皮书《第四编：从治理到产业运营》16.7：委托不自动转授权限，返回内容按数据处理。作为公司设计依据，不能当成本产品已实现控制。
- 项目原有 [数据与证据合同](data-and-evidence.md) 继续有效；Q2Q 的旧提交和测试不能继承成新接入的验证，B2 开始前需重新选定实际工程与接口版本。
- 参考 ChatGPT 讨论仅作需求／方案数据；缓存中的下载包没有可读取附件，本轮未宣称复用了其全部工作包或逐项验收结果。

B1 前需校准的产品问题：最先自动接续的是“同一任务换 Agent／恢复会话”，还是“主 Agent 给子 Agent 分派任务”。两者共享合同与来源模型，但接收回执、默认材料范围和界面入口不同；B0 不依赖这项决定。
