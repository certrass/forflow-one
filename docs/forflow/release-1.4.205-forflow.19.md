# Forflow One 1.4.205-forflow.19 接续预检修正版

2026-09-20，macOS arm64。本轮按用户“做一下查漏补缺”检查 `.18` 的实际链路和规划边界，保持小范围 Beta，不增加自动记忆或新权限系统。

## 发现与修复

| 发现 | 用户可见影响 | 修复 |
| --- | --- | --- |
| 会话读取失败时，保留记录的逻辑把显示状态恢复为 ready | 旧记录仍可能被复制为就绪材料 | 同时检查原始读取阶段；旧记录可阅读，但读取失败阻止交接并说明连接问题 |
| 终端乐观消息和结构化发送队列未接入预检 | 刚发送的纠正未落盘时可能复制旧材料；结构化乐观记录也可能被误当持久记录 | 两种入口都携带未确认发送状态，待确认／失败重试期间禁止复制 |
| 源记录在进入预检前已被截断，或变成系统占位行 | 只看预检本身未截字，不能证明来源完整 | 识别现有有界文本及历史超限占位行；显示具体缺失原因并阻止复制；主动排除的工具诊断不误判为用户文字缺失 |
| 运行／读取状态变化后又恢复，消息数组可能未变 | 旧快照自动重新变得可复制；异步计算指纹期间也可能跨状态 | 将消息和读取／发送／执行状态绑定为预览版本，变化后必须刷新；关闭、禁用、切换来源或计算期间变化均取消旧复制 |
| 计算哈希期间调用方改变材料对象 | 导出内容与指纹可能不一致 | 导出与哈希使用同一个冻结的序列化内容 |
| 错误提示未区分具体原因，来源未记录运行时连接 | 不知道应加载、重试还是处理来源问题 | 提供九类具体原因与处理提示；运行时切换清除旧预览，回执增加连接标识 |

最初用新增测试在旧实现上复现 5 个失败断言，保留于 `qa/forflow19-reproduction.log`；随后扩展临时状态往返、异步竞态、复制拒绝后重试、已排除诊断等用例。修复没有改变主机执行状态源、发送协议或业务授权。
