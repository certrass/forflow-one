## 2026-10-07 · 交接缺口核对

用户指出「同题再做一版」的交接能力有问题。本轮核对源码确认，下面原使用路径提供的是任务模板，不具备当前任务的自动交接能力。后续不能将其作为“同一任务已传给另一个智能体”的实现或验收依据。

用户随后追问「orca 原本不也有这个功能吗」，并提供内置编排的五类使用示例。本轮方向据此校正为：**先复用已有会话接续、分叉和编排机制，再决定还缺哪些产品能力。** 不继续把已经存在的交接和子任务能力重新当作新功能规划。

### 原有能力与本机观察

- `orchestration-usage-examples.ts` 已包含移交活动任务、移交其他工作树、分阶段执行、并行独立任务、拆成小 PR 五类示例。用户贴出的 billing settings 英文指令与其中的内置示例完全一致；它没有提供一项实际账单需求的目标或文件范围。本轮未据此派发账单任务。
- 已安装 `.13` 的 `skills get orchestration --json` 和 `skills get forflow-cli --json` 确认：完整任务移交使用现有工作区／终端交接，受协调的并行与顺序工作使用 Run、Task、Dispatch 和 worker 流程；不需要重新写调度器。
- `AgentSessionContinuationDialog` 已提供目标智能体选择、重点接续与完整记录模式；终端接续优先使用来源会话路径，无路径时使用近期终端记录。`TerminalAgentSessionForkDialog` 已提供新工作区分叉和可编辑上下文草稿。
- 只读 `worktree ps --json` 的实际运行结果显示，当前 `anemone` 的 WorkBuddy 收到含「任务目标：[每个任务使用相同的目标]」等占位符的模板，并回复要求补充目标、资料与验收标准。这直接复现了新增入口没有完成内容交接的问题。

修正次序应为：映射用户动作到以上已有机制，复用来源、启动和执行状态链路；补齐缺失的实际任务内容与材料传递；最后处理入口与说明。独立重做需要的共同基线、结果关联和对比仍须逐项核对，不能从已有编排能力推断这些都已自动完成。

### 已确认的问题

- `ForflowParallelGuide.prepare` 只传递当前项目 ID、操作意图与静态模板，没有传递原任务内容、补充要求、附件、产出或来源会话身份。
- 模板中的目标、参考资料与验收标准仍是占位符，要求用户重新填写。新建对话本身没有建立两次执行属于同一任务的关联。
- 创建参数没有指定共同代码起点。即使用户复制了文字，也不能由此认定两个执行使用相同材料版本和基线。
- 对比入口同样使用占位符，由用户手动加入 A、B 两份产出。
- `ForflowSessionToolbar.test.tsx` 验证的是项目 ID 与模板进入创建弹窗；此前成品场景验证的是草稿和手动文件引用。两者均没有证明真实任务内容、材料和执行版本的交接。

### 已有能力与复用方向

工程已有两类机制：`terminal-agent-session-continuation.ts` 使用保存的会话路径或近期终端记录准备接续；`terminal-agent-session-fork.ts` 使用终端记录、从当前分支创建工作区并准备草稿。这些机制没有接到「同题再做一版」。接续可以复用来源解析和启动链路；分叉当前分支则不能直接当作从共同原始基线独立重做，记录和工作区完整性仍须单独核对。

产品建议是让用户在同一任务下增加一个执行版本：带上有效要求与参考材料，选择智能体，确认将交接的内容后开始。原任务和另一版保留关联，产出能够归回各自版本，再按共同标准比较。

两种用途的输入不同。此前曾向用户询问默认行为，用户明确要求先看 Orca 原有能力；下表作为复用时的语义核对，不记成已确认的新功能范围：

| 用途         | 应传递的内容                                                       | 文件起点                                     |
| ------------ | ------------------------------------------------------------------ | -------------------------------------------- |
| 独立做另一版 | 原始目标、有效补充约束、验收标准、共同参考材料；默认不带第一版答案 | 共同的指定基线或材料版本，输出分别保存       |
| 接着改进     | 上述要求、当前成果、处理进度和未完成事项                           | 明确的当前成果版本，包括需要接续的未提交改动 |

不能只拼接最后一句话或全部聊天：前者会漏要求，后者会混入旧决定、工具输出和第一版答案。交接前应让用户看到整理出的任务要求与材料；只有确实缺失或冲突的内容才需要补充。跨主机路径须确认接收方可读，普通文件夹也要安排独立输出。

### 应补的验收

使用有原始要求、后续纠正及参考文件的真实任务，核对接收端实际收到的内容；检查两版共同要求与基线、输出归属，以及从原任务找到另一版并开展对比的完整过程。另测材料缺失、历史不完整、接续未提交成果、普通文件夹和远端材料。按钮能打开、模板能发送不能替代这组验收。

以上为实施前诊断；本次落地范围与验证见本文开头的「复用现有协作流程」。两版共同基线、自动结果关联与完整对比验收不计入本轮完成范围。

## 使用路径

1. 在会话上方点「并行与对比」。三步引导直接展开，不再藏在操作指引的第三项。
2. 点「同题再做一版」，填写共同目标、参考资料和验收标准，选择智能体。创建后在各自对话中发送任务。
3. 从侧栏逐个打开任务，保存产出与验证记录，并标明版本。引导中的「查看当前任务文件」打开当前工作区文件。
4. 产出齐备后点「准备对比草稿」，修改版本 A、版本 B 与验收要求。创建后，在对话中添加智能体可读取的文件，或直接粘贴产出内容，再发送。
5. 按需求覆盖、正确性、使用体验、剩余工作逐项比较，核对材料依据后选择采用或组合方案。

新建任务的空白输入区也提供「同题再做一版」「对比两份产出」两个模板。开始编辑后收起快捷模板，保留已写内容。所有模板均为草稿；引导本身不创建或启动任务。

Git 项目可以给每版建立独立工作区。分屏共用当前文件，普通文件夹中的任务要分别指定产出文件或目录。跨主机比较时，将材料放在对比智能体可读取的位置，或粘贴内容。

豆包工作伙伴当前接续飞书里的固定单聊，同一伙伴一次在一个任务中使用。它可以与 Codex、Claude、WorkBuddy 并行；两个豆包任务不会自动变成独立对话。选择豆包和从豆包会话打开本引导时，会显示这一说明。
