# Forflow One 自有账号与中文测试版

后续纠正：本版把 8 项交互入门清单错误替换为 6 段说明，并漏译了硬编码的引导浮层；目录覆盖率不能代表逐屏汉化完成。修复及实际渲染验收见 [1.4.205-forflow.3](release-1.4.205-forflow.3.md)。以下保留 `.2` 当时的交付记录。

版本 `1.4.205-forflow.2`，macOS arm64，2026-09-19。依据用户的完整本地化、独立账号服务与 smoke/回归要求开发；自有账号先行，企业 SSO 后续接入。

## 已实现

- 中文目录 14,390 项完整覆盖，占位符检查通过。509 项精确登记为品牌、命令、路径、协议、代码等技术内容。中文包在首次应用界面渲染前加载，保持动态分块；补齐中文字体回退、首次引导和设置说明。
- 原上游生产账号默认为 `login.onorca.dev`，第一版本机私有策略已禁用其认证配置；本版进一步替换残留账号界面并实现 Forflow 自有身份服务。服务地址由部署方配置，没有默认外部账号地址，也不读取 Orca 凭据。
- 管理员可以创建、启停账号及重置密码；失效会话不能继续调用管理接口。停用与密码重置撤销全部会话；管理员重置自己的密码后返回登录。桌面只返回公开身份信息，不将令牌交给 renderer。
- 独立身份服务使用 Node.js 核心模块和 SQLite，没有额外 npm 依赖；包括密码派生、登录限流、角色检查、会话有效期和身份事件审计。账号及审计数据由部署方保管。
- 隐藏上游云分享、中继、支持/赞助和更新入口；主进程请求、Electron 默认会话及浏览器会话阻断已知 Orca 服务域名，Node 请求不自动跟随重定向。上游在线技能安装面板改为离线分发说明，保留本地技能发现。
- 固定 Node 24.14.0 / pnpm 11.19.0；打包前自动执行中文门禁、类型检查、身份服务测试和登记的回归套件。保留真实上游许可证、来源与协议兼容字段。

## 使用

从“应用程序”打开 Forflow One。在「设置 → Forflow 企业账号」登录；本机测试服务地址为 `http://127.0.0.1:43120`，只监听回环网卡。初始管理员及密码位于 `~/Library/Application Support/Forflow One Identity/本机账号.md`，权限为 0600，未包含在安装包或聊天中。

账号服务通过当前用户的 `cn.forflow.one.identity` LaunchAgent 在登录系统后启动。服务程序、数据、安装记录位于 `~/Library/Application Support/Forflow One Identity/`。服务和桌面可分别停止；企业部署时按 [身份服务部署说明](../../services/identity/README.md) 更换为国内/内网 HTTPS 地址。使用独立账号不要求把项目文件上传到身份服务。

用户数据继续使用 `~/Library/Application Support/Forflow One`，原 Orca 应用及配置不被替换。上一版 ZIP 保留，可退出 Forflow 后恢复应用文件；回退 `.1` 不支持新账号界面，身份服务数据须单独保留。

## 验收证据

最终结果以交付目录 `release.json` 和 `qa/` 为准：40 个文件的 459 项单元回归；11 项真实身份服务接口测试；生产安装包的中文 smoke、工作流回归和身份管理回归；安装后复验同一套流程。每份安装包关联源工作树指纹、锁文件和 SHA-256，另核对解压后签名及原 Orca 文件哈希。

此次实测修复了内部技术标识误译、首屏语言加载影响静态启动依赖图、管理员重置自身密码后的过期界面，以及 CLI 返回的英文说明。重启保留设置页但会回到“通用”类别，账号测试通过设置侧栏重新进入，继续验证原会话。

本机包采用 ad-hoc 签名，尚未进行 Developer ID 公证或其他 OS/CPU 验证。国内模型真实调用按用户安排等待凭据；第三方 CLI 输出与代码不作强制翻译。身份审计已实现，业务数据权限、所有 Agent 操作的证据链、独立不可篡改审计存储和 SSO 仍属于后续治理开发；当前测试结果不等同于企业合规验收。
