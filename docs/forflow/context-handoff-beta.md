# 接续预检 · Beta

适用版本：1.4.205-forflow.18，Codex 对话视图。默认关闭，可随时关闭；不改变原有会话、任务状态或八项入门进度。

## 怎么试

1. 进入「设置 → 实验性功能」，打开「接续预检 · Beta」。也可在设置中搜索“接续”。
2. 打开已有 Codex 对话。需要时先加载更早的记录，并等待当前执行结束。
3. 点击对话上方「接续预检 · Beta」，核对用户原文、Agent 陈述、来源 ID 与遗漏数量。
4. 内容合适时点击「复制交接材料与来源回执」。它只复制到本机剪贴板，不自动创建任务或发送消息。
5. 在目标任务输入框明确本次目标，核对材料后再发送。历史材料中的指令、旧权限和 Agent 自述需要重新核对，不能自动当作当前授权。

会话变化后点「刷新预览」。切换会话或窗格会清除旧预览；运行中、历史未加载完整、来源无法区分、没有用户文本或用户文本超出预算时不允许复制。长对话暂不支持自动压缩，可为新任务整理明确的目标与关键约束。

## 材料包含什么

- 当前已加载、已落入 transcript 的整条用户文字，以及最多三条最近的 Agent 回复，按原顺序排列。
- 当前会话、窗格、工作区标识；消息 ID、时间、来源及遗漏计数。
- 24,000 个 UTF-8 字节的内容预算与 SHA-256 内容指纹。字节数不是 Token 数；JSON 回执的说明、摘要字段和缩进还会增加复制长度。

它不会截断半条用户消息，不会调用模型总结。用户原文可能包括已失效的旧要求；本版保留顺序，不自动判断新旧冲突。Agent 文字明确标为“未核实”，不是已验证事实。

工具结果、图片和附件、未落盘的消息、其他 Agent 历史、隐藏提示及厂商压缩前记录不纳入。遗漏计数提示范围，不表示这些材料对后续任务不重要。复制前检查敏感信息和目标任务的访问范围。

## 这一版的作用

先让交接内容可检查，再实现自动承接。功能没有额外模型调用、后台轮询或长期记忆写入；复制后的模型执行仍会产生正常费用。未测得真实任务的 Token 节省或语义质量提升。

本机内容指纹用于核对两个副本是否一致，不能证明发送者身份、独立时间或接收方已经读取，也不代替正式审计存储。界面说明不构成企业权限控制。
