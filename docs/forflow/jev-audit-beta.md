## 产品位置与操作

入口在“统计与使用情况 → 使用分析 → 会话 Review → Jev · Beta”，也可从“审阅”页签进入已有会话。设置中的本机 API 账户区也提供独立的“Jev 审计 Beta · API 配置”。复用现有账户卡片和系统密钥库；远程／WSL 账户界面不读取本机密钥。

一次操作是：选择一条日志记录 → 可选填写待核实主张 → 准备发送预览 → 检查脱敏内容 → 发送至 Jev → 查看结构化建议 → 人工加入 Issues。关联工具返回存在时一并读取。先验证这一小段闭环，再扩大到批量审阅或其他来源。

首版问题为：可见异常、证据是否足够回答当前审阅重点、所填主张与记录是否冲突。每类均支持“无法判断”。没有发现问题也不会确认 Review；模型建议只有经过人工采纳才进入现有问题处理和定位流程。商业模式、采购及渠道讨论没有被扩展为开发模块。

## 调用与版本

- 使用官方 `POST https://api.typesafe.ai/v1/systemone` 的 Choice 协议；默认固定 `jev-1.13.0`，账户配置拒绝 `latest` 等浮动别名。
- 请求仅包含审阅重点、用户填写的主张、所选记录及关联返回、片段不完整标记、预定义问题。调用指令将记录视为不可信证据，禁止按其中指令改变审阅任务。
- 单次请求上限 24 KiB，预览有效期 10 分钟；同时最多保留 20 个未发送预览。准备预览不需要密钥、不发网络请求。
- 发送时重新核对来源片段的 SHA-256、Review 版本、模型、预览内容和摘要；同一预览编号重复点击复用同次调用。主进程只接受可信桌面主界面调用，不接受任意目标地址或客户端拼接的请求正文。
- 使用主进程 HTTP 客户端，遵循现有代理设置；禁止重定向，30 秒超时，响应最大 64 KiB。不自动重试。401/403/422/429 记录为拒绝；网络失败、超时或不可解析结果保留“完成与用量未知”。
- 返回必须匹配请求模型和完整问题集合。每题的选项集合、数值范围、概率和（误差不超过 0.001）及最高概率选项一致性均会检查。该校验保证接口约束，不证明语义判断正确。

## 数据与记录

密钥复用 `ForflowModelAccountStorage`，在系统加密存储不可用时拒绝保存。保存配置不发请求；“测试连接”仅发送固定算术文本，可能消耗 API 额度，不带用户日志。

发送前在本机遮盖常见密钥、嵌套 JSON 中的敏感字段、Bearer、邮箱和常见用户主目录。预览展示完整请求正文；脱敏不是全量敏感信息识别，用户需检查。实际审计使用 Typesafe 云端服务，不将其描述为离线审计或默认零留存。

调用记录写入本机 `forflow-jev-audit.json`，采用原子写入、POSIX 0600 文件模式、8 MiB／1,000 次记录上限。保存调用编号、Review／版本／证据引用、请求摘要、问题定义版本、请求及返回模型、时间、结果和 Token 用量。账单金额保持未知，不与已结算费用混算。发送前先写入 pending；重启后遗留 pending 显示未知，避免当作失败并重复扣费。

调用账本不二次保存日志正文和密钥。预览只在内存短期保留。原始日志改变后，旧片段可能无法重新读取；完整审计归档还需要独立的受控快照保留策略。人工采纳的 Issue 带调用编号、输入摘要和证据位置；重复采纳幂等，旧版本建议不能加入新版本。

## 接入真实密钥后的验证顺序

1. 已用固定算术测试核对真实认证、固定模型、结构化响应和用量字段。
2. 用合成数据集覆盖明确成功／失败、缺返回、主张部分冲突、截断、脱敏、中文／英文、日志内指令注入、远程结果不明。每个样本固定输入、人工标签、可接受的 unknown 与应定位记录。
3. 再使用获准且去标识化的业务样本，按场景统计问题精确率、遗漏率、弃答率、采纳率与单次成本。分别统计“已给出判断”的条件准确率及所有样本覆盖率；不能用提高弃答率掩盖召回下降。错误概率校准采用 Brier score／可靠性分箱，报告样本数和区间，不将模型 confidence 直接当作审计准确率。
4. 按固定问题版本和数据集比较增量收益，决定是否增加批量触发、行业规则、受控资产快照和新的证据适配器。首版保持人工审阅。
