# 新版能力复用核对

2026-10-07。用户要求检查新版错漏，优先使用原有功能，避免另做重复入口。本次以 `vendor/orca/v1.4.220`（`a7927b28ce45cbb044add478d957abe36c99ccd8`）对照国内版 `173c9e6ff6` 及本次修复，重点核对原生聊天、会话接续、编排与审阅。

## 结论与修复

主要错漏在国内版入口与说明，原有执行能力仍在。

1. 操作指引仍指向已撤下的「并行与对比／准备对比草稿」。改为指向现有「智能体协作」中的接续、派生和编排使用方法。
2. 会话中的「审阅结果」丢失当前项目，用户进入后必须重新选择。现在把现有工作区选择器和执行主机传入原来的审阅表单；只预选唯一匹配项，保留用户后续手动选择。远端不可用时显示原有状态，不换成本机项目。
3. 原有接续与派生的可编辑任务草稿直接使用英文和 Orca。模板现通过既有翻译与品牌层展示中文；原始任务内容、来源路径和终端记录保持原文，接续模式与启动逻辑不变。
4. Claude 接续采用草稿投递，成功提示却显示「已发送」。现在沿用原有投递模式区分「草稿已准备，发送后继续」与实际发送成功；不改变发送时机。

同时删除旧占位入口留下的 23 条无引用文案，恢复英文运行时目录的一致性检查。

前一提交已撤下仅带占位符的「同题再做一版」。本次没有新增任务调度、交接、比较或审阅流程。

## 尚未接通的部分

工作区审阅目前读取明确选择的文件并保存版本；所选会话 ID 只用于关联，尚未自动读取新版完整会话记录和全部子智能体产出。此缺口在 v1.4.220 整合时已有记录，不能把文件审阅描述成完整的多智能体结果比较。

需要继续接线时，复用现有会话记录、子任务名册和执行主机状态，接入当前审阅的来源适配层；不新增调度器、状态缓存或另一套比较页。材料归属、文件版本和用户选择仍由原有审阅机制管理。

豆包接续固定的飞书个人单聊，同一伙伴一次由一个任务使用；其与其他智能体并行的能力不等于两个独立豆包会话。WorkBuddy 继续使用厂商 CLI 和现有登录。
