# 任务、并行与审阅入口收敛

2026-10-07。适用于 Forflow One 桌面中文版本，面向用多个智能体处理研发和知识工作的用户。本轮解决首次上手和任务内的下一步选择，不改变执行、账户或远程协议。

## 调研带来的决定

| 公开来源 | 观察到的产品做法 | Forflow One 的取舍 |
| --- | --- | --- |
| [WorkBuddy 新建任务栏](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Task-Bar) | 从输入任务进入对话，任务可独立执行和切换 | 新建任务为首要动作；连接外部任务来源留在原有来源区，不作为开始使用的前置步骤 |
| [Codex app 产品介绍](https://openai.com/index/introducing-the-codex-app/) | 并行任务按项目组织，查看改动与反馈发生在任务内 | 在任务内保留并行入口，文件与改动归到「查看产出」；不让工具排列决定用户流程 |
| [Qoder Quest 概览](https://docs.qoder.com/user-guide/quest/overview) | 集中安排任务、查看执行产出，再进入审阅与提交 | 把我们现有的材料审阅直接接到任务入口，保持「要求—材料—发现」的连续过程 |

这些是官方文档对功能和流程的描述，不是对竞品桌面当前版本的逐屏实测。判断依据是上述机制与本产品实际入口的对应关系；未据此推断用户频率或转化率。Chrome Perplexity 未能成功加载后，改用网页检索并核对官方原始页面。

## 实际界面检查

基线为安装版 1.4.220-forflow.11，使用隔离配置的隐藏 Electron 窗口检查。截图保存于本机 `~/Library/Caches/Forflow One/design/feature-focus/before/`。

| 步骤 | 原问题 | 调整 |
| --- | --- | --- |
| 开始任务 | 使用说明默认折叠，展开后混合任务来源、工作树和文件引用等概念 | 任务页直接提供新建任务、并行做方案、审阅结果；主页突出新建任务 |
| 任务执行中 | 分屏、文件、Git 改动、帮助与关键功能占据同等文字权重 | 并行与审阅保持文字按钮；文件、改动合并菜单；分屏与帮助使用带名称和提示的图标按钮 |
| 检查结果 | 材料审阅位于设置的统计页面内，工具栏「查看更改」容易被当作全部审阅能力 | 新增审阅直达窗口，复用 StatsPane 的项目与对话审阅；原设置入口保持可用 |
| 寻找帮助 | 说明包含多次「不会」「不是」与底层配置细节 | 用动作与位置说明下一步；远程文件可读性、分屏共用文件等实际影响选择的说明仍保留 |

## 功能层级

- 首要：描述任务，在原对话发送与继续。
- 关键扩展：按同一目标另做方案，收集产出后准备比较草稿。
- 结果检查：查看文件或代码改动；按要求选择材料开展审阅；回到原任务继续完善。
- 按需使用：分屏、操作说明、连接来源和高级设置。

并行对比入口准备可编辑草稿，不自动复制所有上下文、不批量启动智能体；原有 Git 与文件夹执行方式保持不变。审阅入口复用原有材料读取和 Jev 流程，不扩大远程材料可读范围。

## 验收

检查新建和并行动作是否进入原有草稿；任务页及会话都能直达材料审阅；审阅返回列表和关闭窗口后原对话草稿保留；文件菜单能打开真实文件树；浅色、深色及窄窗口可读。运行结果记录于对应版本交付说明。
