# Forflow One 界面文案

界面先让用户看懂当前状态和下一步操作。按钮写具体动作，辅助文字解释操作位置或结果，一句能说清就不再补充一段。

## 常用写法

| 场景     | 写法                                          | 使用条件                                   |
| -------- | --------------------------------------------- | ------------------------------------------ |
| 读取账号 | 正在读取账号…                                 | 请求正在执行，刷新按钮禁用                 |
| 已有登录 | 已登录                                        | 已读到账号身份；不代表积分或模型请求已验证 |
| 尚未登录 | 尚未登录。登录 WorkBuddy 后，点击刷新账号。   | 服务明确返回未登录                         |
| 读取失败 | 账号读取失败，请重试。／重试                  | 保留具体问题和一个可执行动作               |
| 切换账号 | 在 WorkBuddy 中登录其他账号，再回到这里刷新。 | 本页只能读取账号，切换动作在来源应用完成   |
| 选择材料 | 选择材料／已选 3 份材料                       | 用数量说明选择结果，来源和技术标识放详情   |
| 发起审阅 | 开始审阅／正在审阅…／查看结果                 | 按实际阶段更新文案                         |
| 继续任务 | 继续对话／发送任务                            | 按按钮实际行为命名                         |

“账户”用于设置分类和账户类型，“账号”用于具体登录身份。保留 WorkBuddy、Codex 等正式名称。CLI、ACP、字节数、原始错误和请求标识留在排查详情，不占用主操作说明。缺少余额时不显示 0；接通积分后再展示真实数值、所属账户和更新时间。

## 连接引导

- 列表先写用途，状态只反映实际检查结果。「已找到连接工具」不写成「已登录」。
- 按钮写对应动作：「查找飞书伙伴」「连接所选伙伴」「查看任务」。多个伙伴用名称选择，编号只留给底层接口。
- 首次设置按步骤展开；已有授权直接连接。应用 ID、启动命令和断开操作放到详情。
- 失败时说明当前问题与恢复动作；不在主流程堆叠 CLI、凭据所有权和历史支持范围。

本轮实现与 QoderWake 参考核对见 [连接引导](connection-guidance.md)。

## 核心功能命名

- 「新建任务」：准备任务与选择智能体；执行从对话中的发送开始。
- 「并行做方案」：同一要求分别完成；「并行与对比」提供另做一版、收集产出、准备比较的操作。
- 「查看产出」：查看文件与代码差异。
- 「审阅结果」：按要求检查选定材料与对话记录，查看和跟进发现的问题。
- 分屏、操作指引使用有可访问名称和悬停说明的辅助图标；不与核心动作争夺文字层级。
