# Orca v1.4.220 与国内版审阅整合

记录日期：2026-10-05。当前工作分支 `codex/upstream-v1.4.220`，候选版本 `1.4.220-forflow.1`。

## 目标与版本

用户要求更新近期 Orca，明确优先“原生聊天与多 Agent”，并补充“国内版我们自己的功能有些需要将 ui 和审阅向新版靠拢”。本轮以当前国内版提交 `b37711fce90ff5b17fbecbf788aa1d52f37719a4` 为基础，整合官方稳定发布 [v1.4.220](https://github.com/stablyai/orca/releases/tag/v1.4.220)，发布提交 `a7927b28ce45cbb044add478d957abe36c99ccd8`，发布时间 2026-10-04 05:01:05 UTC。没有采用发布日之后的 main。

原国内版已包含 v1.4.206；当前安装记录为 `1.4.206-forflow.7`。主工程有在途文档和编号副本，本轮在独立工作树实现，不覆盖主工程未提交内容。v1.4.206 与 v1.4.220 属于不同发布分支，公共祖先为 `b5b727bddbdd34c31801fb125d43eb818cf84a76`；旧分支独有变化仅为发布版本和技能映射记录，映射记录保留。

## 新版与现有审阅怎样结合

新版原生聊天与多 Agent 负责执行任务；现有 Review 负责检查指定版本的交付。代码差异审阅与任务交付审阅分别保留各自对象，围绕工作区、文件和来源版本建立关联。

1. **界面复用。** 项目审阅入口采用新版设置标题和操作槽，来源、依据及信号采用统一分区；审阅详情采用紧凑状态栏和原生按钮组。原有目标追问、逐步选材、原文查看、问题、评论、Jev 预览及人工采纳继续使用同一套账本。
2. **聊天状态复用。** 保留新版队列、目标、子任务列表、后台任务、读取失败与恢复行为。国内版接续预览通过同一聊天会话接入，并把排队消息、未确认发送和后台任务纳入未完成判断。
3. **审阅版本不随聊天漂移。** 审阅仍绑定明确的来源和版本；修订材料后重新读取形成新版本，历史决定留在旧版本，不能把一次确认套到后续输出。

### 已核对的来源边界

当前对话 Review 读取本机 Codex 日志；工作区 Review 读取明确选择的文件并冻结哈希、Git 版本和所选会话 ID。`WorkspaceReviewSource.capture` 已明确记录：关联会话 ID 不等于已读取正文。此次界面适配没有将新版 journal 或全部子 Agent 的输出自动加入 Review。

后续完整接线应复用新版 `agent-session-journal`、子任务名册及执行主机的状态，向现有 Review 来源适配层提供带主机、会话、轮次、子任务和产物版本的证据。首次快照只纳入明确选中的来源，保留未读、仍在运行、未能确认及截断状态；复查沿用现有版本和问题处理流程。不能通过遍历本机日志推断远端子任务已经结束，也不新增另一套 Agent 状态缓存。

## 保留与适配

- 保留中文、Forflow 产品身份、私有部署网络限制、国内模型及 CLI 接入、飞书、用量证据、现有审阅与 Jev 功能。
- 合并上游与国内重复的 CodeBuddy 注册，保留国内命令别名和文档入口；采用新版 CodeBuddy 历史与恢复能力，Qoder CN 保留独立配置。
- 原生聊天跟进按钮保留；结构化聊天使用新版队列、停止和状态组件。结构化聊天仍沿用上游实验开关，未改写用户现有配置。
- 用量分析补入 Muse，并使用新版长上下文计价字段；国内费用覆盖信息与上游缺价状态一并保留。
- Agent 控制设置迁到新版技能安装流程；自定义 Shell 保留路径校验并增加新版启动参数。
