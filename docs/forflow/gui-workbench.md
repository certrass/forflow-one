# 对话与终端工作台

依据用户引用的「私有化治理平台」讨论，改造中间会话窗格，复用现有 Native Chat、工作区和浏览器能力。`.13` 接通显式入口，`.14` 进一步改进文件引用和审阅操作；验证结果见各版发布记录。

## 怎样使用

工作区终端上方提供“对话／终端”“分屏”“并行任务”“文件”“查看更改”。工具栏作用于当前活动窗格；切换视图保留原 PTY 和会话，不重新启动智能体，也不重发历史。

- **对话／终端**：受支持的会话可随时切换。首次使用旧配置时，点击“对话”启用聊天界面；已有标签的视图和默认偏好不做批量迁移。新配置默认在对话中打开受支持的智能体。当前界面一次在同一终端标签内展示一个聊天窗格。
- **分屏**：选择在右侧或下方打开终端。这会创建一个 Shell 窗格，不自动启动第二个智能体，也不创建独立工作副本。
- **并行任务**：打开现有工作区配置，默认沿用当前项目；选择执行空间、填写可选工作区名和智能体后创建，再在新会话输入任务目标。代码修改可使用不同分支的工作树；普通资料任务可使用文件夹。工作树不等于安全权限隔离。
- **文件**：打开当前工作区文件列表。点击文件预览；把文件拖入对话输入区后显示文件名标签，悬停可查看完整路径，点击叉号可移除引用。发送仍携带准确路径。草稿与附件沿用现有按窗格缓存和执行位置校验；发送后的 CLI 历史仍可能显示完整路径。
- **查看更改**：打开原有源代码控制面板，查看工作区实际 Git 更改。这里包含人工和其他进程的修改，不只限于本次智能体；查看不会自动提交或发布。普通文件夹项目不显示这个入口。
- **网页设计与预览**：在原有浏览器窗格打开页面，选择元素、添加修改意见，再用现有“发送给智能体”选择目标。设计意见保留页面与选中元素信息；对话切换不替换这套机制，也不凭终端文字猜测页面结构。

CLI 的权限确认、等待记录、断线和错误仍由原会话路径处理。“对话”按钮只改变显示方式，不赋予新权限。图形输入也不会把全部仓库自动上传；文件引用和实际上传仍由既有本地、SSH、远程执行位置逻辑处理。

## 适用范围

2026-09-20 用户收窄当前开发范围：“gui的适配可以先做codex的适配就好，然后国内的cli先不管”。近期 GUI 开发和专项验收集中于 Codex；国内 CLI 新适配、转录接入和厂商联调暂缓。已有入口与账户配置保留，暂缓不等于删除功能。

Codex 终端桥接会话执行中，输入区新增独立的“补充消息”按钮；“停止智能体”仍可单独操作。补充内容使用原 PTY 输入链路，处理时机由 Codex 决定，不宣称为 Forflow 可管理的消息队列。空草稿、附件尚未准备完成、移动端占用或目标不可写时不能补发；停止保留未发送草稿。该入口不改变结构化会话的发送流程。

本地转录读取支持 Claude／OpenClaude、Codex、Grok、OMP。Grok／OMP 要求转录在当前读取端可访问；远程支持不能仅根据品牌判断。普通 Shell、未识别的智能体和不支持的主机显示原因，仍可使用终端。

CodeBuddy、Qoder CN 等已有启动适配，但尚未新增完整 GUI 转录适配；本次不据此承诺国内执行器的完整上下文读取。Kimi／智谱／DeepSeek 的 API Key 管理也不会自动转化为相应 Agent 的 GUI 会话。

“结构化对话”采用独立会话载体，没有可原样切回的底层终端，因此不显示虚假的“终端”按钮。新配置暂不默认启用结构化执行路径；保留用户已有设置。

## 接续开发

下一阶段应基于具体执行器、固定版本和真实脱敏转录或结构化接口增加适配，再连接任务材料、受控调用回执和成果复核。图形会话、工作树和工具栏本身不构成企业授权、出站网关或正式证据链。

此文中的产品操作已连接现有实现。测试清单及执行证据见本轮发布记录；真实厂商模型调用和客户 SSH 环境需分别验证。
