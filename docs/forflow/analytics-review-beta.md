## 使用路径

“统计和使用情况”分为「概览／使用分析／审阅」三个页签。概览保留账户额度、提供商切换和原有统计；使用分析按用量历史、可展开的高用量会话、模型／项目分布组织。审阅既可从会话展开区进入，也可由页签选择会话。支持时间范围、本机全部日志／Forflow 工作树范围、项目、会话或模型搜索，按最近活动、期间 Token 或已知估算费用排序。默认展示 5 条，显示更多可展开当前页 20 条，支持分页查看全部匹配会话。返回分析保留搜索条件。

选择会话后，Review 保存审阅重点和来源版本。记录页可查看调用及对应返回的本机片段，问题关联具体记录或本次范围；问题可复查解决、说明理由后驳回或重新打开。评论与处理记录带有关联版本。重新读取后，比较新增、变化和本版未再出现的记录；历史来源快照只读，问题状态显示当前决策。确认只针对保存范围与版本。

后续审阅页参照用户提供的 Git PR 截图，新增来源、版本、审阅者、评论、检查、状态和活动记录，复用原版本账本与问题流程。从记录可以直接进入 Jev，预览发送后仅生成建议，人工采纳才进入 Issues；检查按所选版本展示。原概览的每日强度和 Token 分布已保留并在最终包中验证。

界面参照用户提供的四张 Codex Usage 截图：页签、薄边框趋势卡、右侧时段切换、可展开表格和按需展示明细，沿用工程既有颜色、字体与组件。日图补齐日历空白，7／30 天完整显示；较长历史按连续日期区间合并，总量不丢失。Codex 图中缓存为输入子集、推理为输出子集，不重复堆叠；OpenCode 继续以其提供商上报总量展示。套餐历史账期、插件／Skill／消息趋势未接入，通过数据覆盖说明，不用局部工具记录推算全量趋势。

## 数据与版本

- 用量复用 Codex 扫描、去重、计价及会话标题索引。期间数字从单会话来源文件的每日归属汇总，不用会话终身总量替代。旧多会话文件无法逐日分配时明确显示未知。缺价模型不按零元计算。
- 日志读取每次最多 8 个来源文件，各取末尾 2 MiB；Review 每类最多保存 200 行详情。界面保留候选文件数、已读数、失败、截断、损坏、冲突及未见返回的数量。超出窗口的记录、受控数据访问回执与资产版本仍未覆盖。
- 工具与响应按会话、回合和记录 ID 关联，避免跨会话误配。相同标识但内容不同会记录冲突。调用和返回保留各自来源位置与内容哈希。
- Review 版本包含用量快照、审阅重点、来源窗口、SHA-256 及解析器版本。确认前重新扫描并核对当前版本。重新打开会话也会核对来源，变化后追加版本，旧确认不用于新版本。问题不会因为记录消失而自动解决。
- 本机账本位于当前应用数据目录的 `forflow-session-reviews.json`，原子写入，带修订号并发检查；损坏账本不会被自动清空。范围／期间分开保存。最多 1,000 份审阅、每份 100 个来源版本、账本 32 MiB，达到上限会报告错误。
- 原始日志不改写，日志正文不进入审阅快照；按需读取正文时先验证保存窗口的哈希，再遮蔽常见凭据与邮箱并限制展示长度。这不是完整敏感信息识别。用户主动写入的问题、评论和处理说明保存在本机。

核心 Review 是可持久化的本机审阅工作台，不依赖外部自动评审模型。可选 Jev 接入另见 [Jev Beta](jev-audit-beta.md)，真实中文样本与整包流程验收见 [最新回执](jev-review-validation-20260921.md)；多人身份审批和完整执行证明尚未接入。未见返回表示证据缺口，不判为失败。这里不判定 SSH 主机的执行存活状态。

## 验证入口

- `src/main/codex-usage/codex-review.test.ts`：期间归属、分页排序、未知价格、跨会话／回合隔离、持久化、并发、来源变化、历史问题、损坏账本及片段校验。
- `tests/forflow-packaged/session-review.spec.ts`：隔离配置与模拟日志，隐藏窗口实际执行筛选、来源查看、问题、评论、重载恢复、版本比较、历史只读和确认；截图覆盖浅色与窄屏深色。
- `.forflow/evidence/forflow25-live-readonly.json`：直接读取本机当前缓存和真实日志的独立核对。该检查不写真实审阅记录；缓存扫描时间单列，不将缓存当成最新扫描。

版本和最终检查结果见本轮发布回执；开发测试、候选包与安装状态分别记录。
