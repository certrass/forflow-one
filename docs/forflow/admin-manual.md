# Forflow One 管理员手册

适用版本：**1.4.205-forflow.7 · cn-private**。更新日期：2026-09-19。本版交付验证环境为 macOS arm64，身份服务使用 Node.js 24.14.0。面向内部试用和部署准备；客户生产拓扑、平台兼容和审查清单需另行验收。

用户操作见 [操作手册](user-manual.md)，身份服务精确命令及接口约束见 [服务说明](../../services/identity/README.md)。

## 1. 先选择运行方式

| 方式                    | 数据和执行位置                                             | 当前适用范围                                               |
| ----------------------- | ---------------------------------------------------------- | ---------------------------------------------------------- |
| 本机使用                | 桌面与项目在本机，智能体使用本机 OS 身份                   | 当前安装验证基线；不要求先建企业账号                       |
| 本机桌面＋自有身份服务  | 身份数据库在团队国内／内网服务；项目、CLI 仍按所选主机运行 | 已实现账号、成员管理和身份审计；登录不会自动限制本地项目   |
| SSH 工作区              | 项目和执行器在 SSH 主机，客户端展示结果                    | 继承上游能力，按实际主机准备依赖及权限；未完成客户环境验收 |
| 远程 Forflow One 服务器 | 连接自托管运行时管理任务                                   | 界面标注测试版；配对令牌不是企业用户 RBAC，需专项验证      |

首个内部试点采用本机桌面和测试仓库，逐一接通账号、执行器和模型，再验证远程执行。不要让业务成员共享管理员或通用运行时凭据。

## 2. 分发、升级与回退

1. 使用团队提供的 Forflow 安装包和该包的 `release.json`；核对版本、目标架构及 SHA-256。可用 `shasum -a 256 安装包路径` 与回执对照。
2. 确认用户打开的是 `/Applications/Forflow One.app`。原 Orca 保留为独立应用，不迁移其凭据，不覆盖它的目录。
3. 升级前记录旧版、备份应用和 Forflow 配置，确认工作区内未提交改动。应用数据、Git 项目、第三方 CLI 配置和身份数据库分别备份，不能只复制 `.app`。
4. 关闭应用后替换包，重启核对版本、图标、八项入门进度、既有项目和关键权限。新权限助手按系统要求重新授权。
5. 有问题时恢复旧应用和与之匹配的配置快照，保留当前故障数据用于诊断；涉及数据库结构变化时先验证回退兼容性。

本版为本机签名的内部测试包，尚未正式公证；Windows、Linux 与其他 CPU 的 Forflow 包未交付验收。私有版不使用 Orca 在线更新渠道。构建者按 [构建说明](build-and-localization.md) 生成制品，不使用原上游发布脚本代替 Forflow 流程。

## 3. 部署自有身份服务

### 3.1 准备与初始化

准备独立服务账号、私有数据目录和 Node.js 24.14.0；复制 `services/identity` 及所需许可证。该服务无额外 npm 依赖。离线环境仍需预先准备并核验匹配目标 OS／CPU 的 Node 发行包。

在服务目录执行初始化命令：

```sh
node manage.mjs --data /absolute/private/identity bootstrap
```

把 `/absolute/private/identity` 替换成实际目录。通过标准输入传入 `username`、`displayName`、`password` 的 JSON；密码至少 12 字符。使用受限的本机输入流程或权限为 0600 的临时文件重定向，不把密码写进命令参数、共享脚本或工单。已初始化的目录不能再次 bootstrap。

### 3.2 启动与联网

| 配置                                                    | 要求                                         |
| ------------------------------------------------------- | -------------------------------------------- |
| `FORFLOW_IDENTITY_DATA`                                 | 必填，身份数据库目录；禁止放入公开 Web 路径  |
| `FORFLOW_IDENTITY_TENANT`                               | 默认 `forflow`；首次初始化绑定后不得随意改变 |
| `FORFLOW_IDENTITY_HOST`、`FORFLOW_IDENTITY_PORT`        | 默认 `127.0.0.1:43120`                       |
| `FORFLOW_IDENTITY_TLS_CERT`、`FORFLOW_IDENTITY_TLS_KEY` | 直接提供 HTTPS 时配置证书链与私钥路径        |

配置后在服务目录运行 `node server.mjs`。无 TLS 时服务只允许回环监听；团队访问采用可信 HTTPS，可通过同机反向代理接入。桌面端拒绝明文远程 HTTP、地址中携带凭据、重定向及 Orca 上游身份地址。

反向代理限制请求体为 8 KiB，配置速率和连接超时，不记录 Authorization 或请求体，不为身份接口开放 CORS。使用 `GET /v1/identity/config` 检查产品、合同版本、租户和认证类型，再在桌面「Forflow 企业账号」保存地址并登录。不能仅凭端口可达判断服务配置正确。

### 3.3 成员和会话

管理员可在桌面创建成员、启用账号、停用并撤销会话、重置密码及核验最近身份审计。最后一个管理员受保护，不能被停用。普通成员无管理接口权限。

当前会话最长 4 小时，空闲 30 分钟失效；停用和密码重置撤销该成员全部会话，退出撤销当前会话。桌面系统安全存储可用时加密保存凭据；不可安全保存时只保留在当前进程。

上述撤销针对身份服务会话，不会自动杀掉外部 CLI、撤销厂商令牌或收回已读入本机的文件。离职和权限收回还应处理 OS、Git、SSH、模型服务及执行进程。

管理员密码遗失时按服务说明使用本机 `reset-password` 恢复，输入仍走标准输入；操作留存身份事件并撤销旧会话。当前没有 SSO、公开注册或自动邮件找回流程。

## 4. 管理国内 CLI 与模型

把以下配置归属到**实际执行主机**，逐项登记：CLI 名称与固定版本、二进制摘要、配置目录、认证方式、模型及地域、接口地址、凭据引用、允许工具和出站策略。

CodeBuddy、Qoder CN 已有启动适配；它们与 WorkBuddy、QoderWork 桌面应用分别安装、认证。豆包／火山方舟通过模型或工具接入，不建立虚构的 `doubao` 编程命令。来源和示例见 [国内 CLI 说明](domestic-cli.md)。

本版有关闭部分厂商遥测／更新的启动配置和模板，模板不会自动写入所有用户的厂商目录。应在固定 CLI 版本上检查配置是否生效，并核对登录、计费、下载、插件和模型请求的目标地址；“国内厂商”本身不证明离线可用。

初次联调使用合成仓库：读文件、修改、测试、拒绝一次写入、取消、恢复，再检查产物和网络记录。真实国内 API 尚未在本项目完成验证。凭据配置准备好前，不用假模型结果替代厂商验收。

## 5. 权限、上传与出站控制

| 控制层           | 本版能力                           | 管理员需补齐的工作                               |
| ---------------- | ---------------------------------- | ------------------------------------------------ |
| 企业身份         | 成员管理、登录、会话撤销、身份事件 | 接入工作区及数据授权；SSO 后续开发               |
| 本机／远端 OS    | 沿用操作系统及 SSH 身份            | 最小权限执行用户、目录权限、密钥分配与撤回       |
| 智能体           | 默认保留新增执行器的权限确认       | 固定厂商版本验证，限制工具和可访问范围           |
| 浏览器与应用上传 | 来源确认、权限提示、所选文件确认   | 目标白名单、数据分类和远程暂存策略               |
| 系统网络         | 阻断已接入策略的上游产品服务       | 覆盖任意终端、CLI、MCP、浏览器的网关／防火墙控制 |

私有构建阻断上游云账号、分享、中继配置、推送、遥测、诊断上传、插件 Git 下载和在线更新等受控路径。它不是通用网络隔离系统。本地诊断文件仍可能存在，应管理访问与留存；关闭上传不等于不产生诊断。

操作系统权限按用途申请：计算机控制、录屏、通知、受保护文件夹分别检查。不要要求所有试用人员一开始开启全部权限。浏览器确认取消后不发送文件的本机路径已经测试；外部 CLI 自行发送及全部远程组合不在该测试范围内。

## 6. 审计、备份与恢复

身份服务记录账号创建、登录结果、退出、启停、密码重置和受限请求。可以在服务目录执行：

```sh
node manage.mjs --data /absolute/private/identity verify-audit
```

核对记录数量、链头与完整性结果。当前为数据库内的关联哈希和修改防护；具有 OS／数据库管理权的人仍可能重写全链或截断尾部，不能称为独立不可篡改证据库。完整任务、工具、模型、文件和业务复核审计尚未打通。

备份时优雅停服，完整复制身份数据目录，包括尚存在的 WAL／SHM 文件；限制备份访问并记录版本和摘要。在隔离目录演练恢复和链核验，再执行恢复后的会话撤销流程，要求成员重新登录。不要直接以旧备份重新启用生产中已失效的会话。具体恢复／批量撤销步骤需在客户运维方案中演练，不把本文当自动恢复脚本。

日志留存期限按客户实际义务和数据类型确定；首版没有内置客户统一留存承诺。与公安部第 176 号令等要求的对应建设另见 [数据与证据方案](data-and-evidence.md)，本手册不构成产品认证或客户合规结论。

## 7. 交给测试人员前的验收

1. 包：版本、架构、摘要、安装路径、原应用保留和回退副本。
2. 工作流：添加测试项目、新建两个工作树、编辑、测试、审阅，核对八项入门入口和进度。
3. 接入：分别记录 CLI 检测、认证、真实模型调用、历史读取和恢复结果，不合并成一个“接入成功”。
4. 权限：普通用户不能管理成员；账号停用后旧身份会话失效；必要系统权限实际可用；本机上传取消／允许与接收端结果相符。
5. 网络：列出应用及执行器请求目标，核对被禁止的上游服务与获准的模型、Git、制品来源。
6. 恢复：身份数据备份可恢复、审计链可核验、旧会话不会重新获得效力。

按目标环境完成这些检查后，记录版本和证据位置。`.7` 本机发布验证已通过的范围见 [版本记录](release-1.4.205-forflow.7.md)；客户环境、实际国内调用或恢复演练未执行的条目仍标待验证。
