# 飞书任务与任务清单

适用：Forflow One .16 本机测试版。首期通过官方飞书 CLI 的个人授权，只读获取飞书任务与任务清单，再导入为工作区会话草稿。

## 第一次连接

进入「设置 → 集成 → 飞书任务」。本机需安装官方 `@larksuite/cli`，本次适配依据为 1.0.84；应用内提供可复制的安装、配置和授权命令及官方文档入口。

1. `npm install -g @larksuite/cli`：由使用者或管理员安装官方工具。
2. `lark-cli config init --new`：按 CLI 提示在飞书配置应用。已有应用时按官方配置文档选择已有应用。企业管理员可能需要批准权限。
3. `lark-cli auth login --scope "task:task:read task:tasklist:read offline_access"`：授予个人任务读取及刷新权限。
4. 回到 Forflow，点击「连接本机飞书」。多账号环境可填写应用 ID；授权命令也应使用同一 `--profile cli_...`，避免给另一个应用授权。

Forflow 保存应用 ID、个人 ID 和显示名，使用官方 CLI 管理的凭据，不复制长期令牌到智能体环境。连接绑定当前个人身份；本机 CLI 后续换人时读取会中止，需重新连接。断开只移除 Forflow 的绑定，不退出 CLI 或其他工具的登录。

本机连接与任务读取暂不在 SSH、WSL 或远程服务器上执行。切到远程运行环境时界面停止本机读取；返回本机再操作。导入后可在创建窗口明确选择其他执行位置，任务说明会随草稿传到所选执行主机，发送后按所选智能体的模型配置处理。

## 从任务开始工作

1. 「设置 → 集成」点击「浏览任务」或「打开飞书任务入口」。此前隐藏的来源会由这个操作重新显示。
2. 选择「我的任务」，或点击「读取任务清单」后选择某个清单。选择未完成／已完成，再点击「读取任务」。每页最多 50 项，按需加载更多；搜索仅覆盖已加载结果。
3. 点击「查看任务」，读取最新详情。界面展示标题、说明、任务 ID、来源链接、读取时间及导入范围。
4. 点击「选择项目并准备对话」。选择 Git 项目／普通文件夹、执行位置和 Codex，编辑「这次要完成什么？」。已有 Git 项目可用独立工作树并行处理。
5. 点击「创建并准备对话」。任务说明进入同一创建流程的对话草稿，**点击发送后才执行**。可继续拖入文件引用。
6. 通过「文件」「查看更改」「浏览器」检查结果，再在会话里补充要求。Git 改动面板包含整个工作区的更改，不天然等于本任务专属产物。

导入副本包含任务 ID、标题、说明、来源 URL、源更新时间和获取时间。它不包含评论、附件或清单全部内容；不会自动下载附件、完成任务、发消息或回写飞书。重复导入会创建新的工作区草稿，不进行双向同步或自动去重。

## 排查

- 找不到 CLI：先在系统终端运行 `lark-cli --version`，确认可执行路径已进入 PATH，再正常重启 Forflow。
- 缺少应用配置：执行 `config init`，CLI 显示的配置完成才代表应用准备好。
- 缺少读取权限：应用和个人授权都需要对应任务／清单权限。按上面的 scope 重新登录，不以机器人身份替代个人权限。
- 已绑定但读取失败：绑定仅确认本机授权元数据；实际访问权和网络在读取时验证。检查网络、登录和权限后点击读取重试。
- 列表为空：检查清单和完成状态；搜索只覆盖已加载结果，分页提示未消失时可加载更多。
