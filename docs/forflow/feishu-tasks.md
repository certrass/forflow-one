# 飞书任务与任务清单

适用：Forflow One .20 本机测试版。首期通过官方飞书 CLI 的个人授权，只读获取飞书任务与任务清单，再导入为工作区会话草稿。

## 第一次连接

进入「设置 → 集成 → 飞书任务」。本机需安装官方 `@larksuite/cli`，本次适配依据为 1.0.84；应用内提供可复制的安装、配置和授权命令及官方文档入口。

1. `npm install -g @larksuite/cli`：由使用者或管理员安装官方工具。
2. `lark-cli config init`：按 CLI 提示选择“已有应用”或“新建应用”。复用已有应用时提供 App ID 与 App Secret；不要把密钥发到聊天或写入 Git。企业管理员可能需要批准权限。已有 CLI 应用配置时跳过此步；安装了飞书客户端不代表 CLI 已配置。
3. `lark-cli auth login --scope "task:task:read task:tasklist:read offline_access"`：授予个人任务读取及刷新权限。
4. 回到 Forflow，点击「连接本机飞书」。多账号环境可填写应用 ID，界面的个人授权命令会加入同一 `--profile cli_...`，避免给另一个应用授权。这个按钮检测并绑定已完成的个人授权，不会自动创建应用或登录。

Forflow 保存应用 ID、个人 ID 和显示名，使用官方 CLI 管理的凭据，不复制长期令牌到智能体环境。连接绑定当前个人身份；本机 CLI 后续换人时读取会中止，需重新连接。断开只移除 Forflow 的绑定，不退出 CLI 或其他工具的登录。

本机连接与任务读取暂不在 SSH、WSL 或远程服务器上执行。切到远程运行环境时界面停止本机读取；返回本机再操作。导入后可在创建窗口明确选择其他执行位置，任务说明会随草稿传到所选执行主机，发送后按所选智能体的模型配置处理。

## 从任务开始工作

1. 「设置 → 集成」点击「浏览任务」或「打开飞书任务入口」。此前隐藏的来源会由这个操作重新显示。
2. 选择「我的任务」，或点击「读取任务清单」后选择某个清单。选择未完成／已完成，再点击「读取任务」。每页最多 50 项，按需加载更多；搜索仅覆盖已加载结果。
3. 点击「查看任务」，读取最新详情。界面展示标题、说明、任务 ID、来源链接、读取时间及导入范围。
4. 点击「选择项目并准备对话」。选择 Git 项目／普通文件夹、执行位置和 Codex，编辑「这次要完成什么？」。已有 Git 项目可用独立工作树并行处理。
5. 点击「创建并准备对话」。任务说明进入同一创建流程的对话草稿，**点击发送后才执行**。可继续拖入文件引用。
6. 通过「文件」「查看更改」「浏览器」检查结果，再在会话里补充要求。Git 改动面板包含整个工作区的更改，不天然等于本任务专属产物。

导入副本包含任务 ID、标题、说明、来源 URL、源更新时间和获取时间。它不包含评论、附件或清单全部内容；不会自动下载附件、完成任务、发消息或回写飞书。重复导入会创建新的工作区草稿，不进行双向同步或自动去重。

## 排查

- 找不到 CLI：先在系统终端运行 `lark-cli --version`，确认可执行路径已进入 PATH，再正常重启 Forflow。
- 尚未配置飞书应用：完成第 2 步后再执行第 3 步；反复点击连接不能代替应用配置。`.20` 识别官方 CLI 的 `config/not_configured`，不再合并成网络／登录失败。
- 缺少应用权限：由应用管理员在开放平台开通任务／任务清单权限并发布；个人重新登录不能代替应用权限配置。
- 缺少个人读取权限或登录过期：按第 3 步为同一应用重新授权，不以机器人身份替代个人权限。
- 网络失败：检查代理、DNS 和证书后重试，不因网络失败重新创建应用。
- 已绑定但读取失败：绑定仅确认本机授权元数据；实际访问权和网络在读取时验证。检查网络、登录和权限后点击读取重试。
- 列表为空：检查清单和完成状态；搜索只覆盖已加载结果，分页提示未消失时可加载更多。

## 依据与验证范围

官方 CLI 文档：[larksuite/cli](https://github.com/larksuite/cli)。本次源码合同锁定 [v1.0.84](https://github.com/larksuite/cli/tree/2d787fe5d6f35e279f39fe630328ad3689bf2aff)：`auth status --json`、个人身份、`task tasklists list/tasks`、`task tasks list/get`、显式分页与 JSON 响应。

开发机 CLI 1.0.84 本次实际复现了退出码 3、`config/not_configured`；该状态与未安装 CLI、个人登录失效、应用权限不足分开处理。错误类型依据 [官方错误合同](https://github.com/larksuite/cli/blob/2d787fe5d6f35e279f39fe630328ad3689bf2aff/errs/ERROR_CONTRACT.md)，不直接展示可能含凭据的原始错误文本。单元与成品测试使用隔离的 CLI 合同夹具；实际租户授权、管理员审批及真实飞书接口仍需在配置后验证。版本发布结果见本版发布回执。
