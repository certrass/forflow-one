# Forflow One 自有身份服务

首版自部署账号服务，账号数据、会话和身份事件审计均保存在部署方目录中。桌面端仅连接用户配置的地址，未配置时使用本机项目模式；没有默认云账号、公开注册或外部身份依赖。首版账号作用域是团队账号管理；本机文件、终端和第三方智能体仍由操作系统及各自授权控制，不能把登录状态当成工作区授权或业务操作审计。

## 运行与初始化

使用 Node.js **24.14.0**（内置 `node:sqlite`，此版本会输出实验性 API 提示），没有额外 npm 依赖。复制此目录和上游 MIT 许可到国内服务器或内网主机即可运行。离线交付需同时准备经过核验、匹配目标 OS/CPU 的 Node.js 发行包；本轮验证主机为 macOS arm64。

1. 为服务建立独立低权限 OS 用户和私有数据目录；应用自动设置目录 0700、数据库 0600。不要放入公开 Web 目录。
2. 执行 `node manage.mjs --data /absolute/private/identity bootstrap`，通过标准输入提交 JSON 对象，字段为 `username`、`displayName`、`password`。密码至少 12 字符；不要通过命令行参数、终端历史或共享环境变量传递密码。可由受限的 0600 临时文件重定向输入，完成后删除。已有用户时 bootstrap 会拒绝执行。
3. 设置下表中的路径与监听配置，执行 `node server.mjs`。无 TLS 时仅允许监听 `127.0.0.1` 或 `::1`；对团队开放时配置可信 TLS，或由同机反向代理提供 HTTPS。
4. 在桌面端「设置 → Forflow 企业账号」填写 `https://身份服务域名`，保存并检测，再使用已初始化的管理员账号登录。开发机可使用 `http://127.0.0.1:43120`。
5. 管理员在桌面端创建成员、停用/启用账号、重置密码、核验最近身份审计。普通成员不能使用管理接口。最后一个管理员不可被停用。

| 配置                        | 含义                                                             |
| --------------------------- | ---------------------------------------------------------------- |
| `FORFLOW_IDENTITY_DATA`     | 必填，身份数据库与审计目录                                       |
| `FORFLOW_IDENTITY_TENANT`   | 租户标识，默认 `forflow`；数据目录首次初始化后绑定，不能随意更换 |
| `FORFLOW_IDENTITY_HOST`     | 默认 `127.0.0.1`                                                 |
| `FORFLOW_IDENTITY_PORT`     | 默认 `43120`                                                     |
| `FORFLOW_IDENTITY_TLS_CERT` | PEM 证书及中间链路径                                             |
| `FORFLOW_IDENTITY_TLS_KEY`  | PEM 私钥路径，限制为服务账号可读                                 |

反向代理需限制请求体到 8 KiB、设置合理的请求速率和连接超时、不记录 `Authorization` 或请求体；不要将身份接口开放 CORS。服务自身拒绝非约定浏览器 Origin、查询参数和未知接口。桌面端不接受明文远程 HTTP、地址内凭据、重定向或 Orca 上游服务地址。服务健康合同为 `GET /v1/identity/config`，仅暴露产品、合同版本、租户标识与认证类型，不列出账号。

## 密码、会话和审计

- 密码使用独立随机盐和 scrypt（N=131072、r=8、p=1）派生，校验为恒定时间比较；参数参照 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。未知账号执行相同派生成本。每账号 15 分钟最多 5 次失败尝试，计数保存在数据库；单进程最多并行处理 2 个密码请求。
- 登录令牌为 32 字节密码学随机值，服务仅存 SHA-256；有效期 4 小时、空闲 30 分钟。停用账号、重置密码立即撤销其所有会话；退出撤销当前会话。桌面凭据通过 Electron safeStorage 加密，不可用或 Linux `basic_text` 时仅保留在进程内，令牌不进入 renderer 返回值。
- 记录账号创建、登录成功/失败、退出、启停、密码重置和受限请求；每条带序号、时间、租户、操作者、对象、结果及服务生成的 request ID，不记录密码、令牌或业务内容。
- 身份数据变更和对应成功事件在同一事务提交；审计 SHA-256 前向关联，普通 SQL 更新/删除触发器拒绝修改。启动及管理员核验时检查完整性。拥有数据库和 OS 管理权的人仍可重写整条链或截断尾部，因此这不是独立不可篡改审计存储。客户生产建设应把校验摘要和事件定期送入独立的审计/WORM系统，并按客户适用期限管理。

运行 `node manage.mjs --data 数据目录 verify-audit` 输出记录总数与链头；`users` 只列公开账号字段。遗失管理员密码时，可在有 OS 管理权的控制台用 `reset-password`，通过标准输入提供 `id`、`password`，操作会记录为本机管理员事件并撤销旧会话。

## 运维与后续 SSO

服务日志仅输出监听地址及启动错误码，不打印请求体。监控进程存活、磁盘空间、失败登录数量和链校验结果；数据库备份应在优雅停服后完整复制数据目录（包含 WAL/SHM），并在隔离目录演练恢复与链核验。升级先备份，使用同租户启动新版，不直接用备份恢复生产中的失效旧会话；恢复后应撤销现有会话并要求重新登录。首版不自动删除审计记录，没有已配置的客户留存承诺。

SSO 下一阶段扩展认证适配层：保留稳定用户 ID、成员状态、角色、会话撤销和审计接口；新增 OIDC 授权码 + PKCE、明确 issuer/audience/state/nonce 校验和外部身份绑定。当前没有启用或虚构 SSO 跳转。

复验：`node --test identity.test.mjs`。桌面集成测试使用独立临时服务、一次性账号和 HOME，覆盖实际中文设置页、会话恢复、停用撤销、密码重置、断线与本机模式切换。完整记录随 Forflow One 安装包交付。
